# 云电脑经本地网络出网（方案，尚未实施）

需要时再做。本文只记录做法，不包含可运行脚本、账号、密钥或代理地址。

## 要解决的问题

Cursor 云电脑的浏览器从云端自己的地址出网。机器人平台开着时，它的桌面浏览器走本机 `127.0.0.1:8791`，出口在用户这边。这台云电脑没有这条隧道，所以有的站点在机器人电脑上能开，在云电脑上会被拦截。

目标是让云电脑的浏览器改走用户电脑的出口。技术就是代理：云端把请求送进隧道，用户电脑再转发到网站。

## 方向

云电脑访问不到用户电脑上的 `127.0.0.1`。必须由用户这边先把隧道挂出来，云端再去连一个它能够访问的地址。

两边各一段，以后再写：

- 用户电脑：转发。把从隧道进来的请求，用自己的网络发出去。电脑和这段进程要一直开着。
- 云电脑：接入。浏览器实际使用这条代理。只把进程跑起来、浏览器仍然直连，出口不会变。

也可以在云电脑上安装 VPN 客户端，连到用户自己的 VPN 服务器。效果相同：出口变成用户那边。机器人平台的 `8791` 不会因此出现在云电脑上。

## 和机器人平台的差别

机器人平台把隧道装在软件里，用户开着平台，桌面浏览器就被带上 `8791`。云电脑没有这段软件，所以要自己接。原理相同，接线不同。

## 以后实施时要对上的几点

- 代理或 VPN 服务器必须从云电脑连得上。家里的局域网地址不够。
- 浏览器要明确走代理（进程环境或浏览器自身的代理设置）。系统里其它程序是否跟着走，实施时再定，避免把不该走代理的流量也带上。
- 云电脑重开会丢掉当次安装和临时配置。要长期使用，把代理地址和启动方式留在环境里，不要把密码、密钥写进仓库。
- 隧道断开时，浏览器应能看出来仍在直连，而不是假装已经走了用户网络。
- 这一块和业务用例分开。实施时不改现有测试框架，除非那时明确要让某次回归走这条出口。

## 现在不做

不写双方脚本，不在云电脑上改网络，不安装 VPN，不把任何地址或密钥放进本仓库。
