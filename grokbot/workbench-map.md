## 规则

0. 先分账号：查表和写表都必须先看「账号」。不同 Grok Bot 账号的机器人 id、对话、派单不得写进同一行，也不得互相续聊。
1. 两条通道：思考、方案、代码草稿走工作台，默认 Grok 4.7。需求分析默认走该项目需求分析机器人的工作台，一条需求一条对话；执行测试仍由各项目机器人自己做。升级走常驻 Ask/Plan/Debug/Multitask 和 ask_cursor，一事一案一 Agent 一 PR。工作台不替代升级，不按号复制这四个席位。
2. 怎么建：登记时对话列先空，状态为「空」。第一次真有思考、方案或代码活才建对话，建完改成「在用」。日报、走查、周报只出报告的号，没这类活就不建对话。nova 各号状态为「暂停」，对话列留空，不派活、不叫醒。小程序不进本表，总控不管。
3. 何时新开：同一账号、同一机器人、同一项目的常驻对话必须续聊。只有三种情况可新开常驻，并且先由总控把旧 URL 写入「上一条 URL」、旧行改「停用」：对话打不开、已过期或无法继续；已串项目，或同一问连续两次答非所问；新启用非 nova 号且有第一笔这类活。换一天、换用例都续聊常驻。跨项目框架问题进常驻 Plan。需求分析另按「一条需求一条对话」；并发在用的需求分析对话上限 5 条。
4. 关闭需求分析对话：四项齐了才能关：需求标识；用例库标题和读回；知识库标题和读回，或写「无新增」；待确认已标明或写「无」。当天读回一致就关，不等收工，不因换日自动关。分析中、没写回、读回不一致：不关。过期对话要迁移，不当成已回收。
5. 派单简报：必填：账号；项目；任务一句；依据（没有就写「无依据，停」，这份不发）；禁做；已完成与证据位置；交付物和交齐标准；模型 Grok 4.7；续聊：是或否。禁做固定带上：不点页面，不跑业务测试，不写测试结论，不写凭证，不开 PR，不合并 PR。缺一项不派。
6. 核验与汇报：机器人自己核，对照依据原句；代码在自己环境复跑。Cursor 说通过不算通过。给用户的回答要精简，先说结论，只写自己核过的事实和对话链接，不含凭证。要改共享框架并开 PR 时，工作台停笔，改走 ask_cursor。
7. 派单记录：每笔一行：账号、日期、项目、机器人、续聊或新建、任务一句、对话 URL、核验结果。无新派单不写。工作台不占升级每日额度。
8. 状态：只用：在用、空、停用、暂停。旧表里的「已完成」在历史行记入「替换原因」，状态改为「停用」。
9. 换账号：新账号重建后机器人稳定 id 会变，必须新登记一个「账号」，不要把旧账号 id 当成新号已经存在。旧账号行保留并标停用或暂停，便于对照。GO电子是壳号，只接协作与故障通知，不建工作台。GO 暂无需求分析工作台。
