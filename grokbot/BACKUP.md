# Git 与 Google Drive 备份怎么分

两个 Grok Bot 账号（sacks、Faker）共用同一个公开仓库和同一份 Google Drive「QA机器人备份」文件夹。日常先把共用内容同步到 Git，再按账号把压缩包备份到硬盘。

## 说明放哪

这份说明放在 Git：`grokbot/BACKUP.md`。两边拉同一份仓库，规则就一致。不要只放在硬盘备份包里，免得各写各的、对不上。

硬盘包里的 `RESTORE.md` 只写「本账号怎么恢复」，并指向本文件。不要把整份规则再抄进包里当正本。

## 三处各放什么

| 放哪 | 放什么 | 谁用 |
|--------|--------|------|
| Git 仓库 qa-agent-team 的 `grokbot/` | 角色说明、花名册、共用技能的脱敏副本、协作规范、本说明、工作台映射 | 两个账号都拉、都按这个对齐 |
| Google Drive「QA机器人备份」 | 按账号分开的周备份压缩包，用来恢复「这一个 bot 账号」 | 各账号只写自己的子目录 |
| 各项目 Notion 知识库 | 业务知识、用例、缺陷、测试日志 | 不进 Git，也不进硬盘压缩包 |

密码、token、密钥、测号明文、Cookie、.env：三处都不写。测号去哪找，见 `HANDOFF.md`。

## Git 里不放什么

- 记忆正文（profile / journal 导出）
- 现网例程的提示词全文打包（例程跟账号走，进硬盘包）
- Drive 备份压缩包本身
- 凭证、表链接、Notion 页面链接、邮箱

工作台对话地址和对话 id 按既有约定，只写在 `workbench-map.md`。

两边对齐技能和职责：拉仓库，有改动就开 PR。不要用硬盘包去覆盖仓库里的技能副本。仓库技能以现网为准，改完再回写仓库。

## 硬盘包里放什么

每个账号每周日做一次完整备份，传到：

`QA机器人备份/<账号名>/qa-backup-weekly-<账号名>-<YYYYMMDD>.zip`

账号名只用 `sacks` 或 `Faker`。只清理自己子目录里的旧包，只留自己最新一份。禁止删另一个账号的子目录，也禁止删根目录下对方的文件。

包里只放：

- 本账号能读到的记忆导出（自己的和共享的 profile / journal）
- 本账号机器人名单（名字、标题、描述和对应 json）
- 本账号例程（名字、时间、提示词）
- 本账号的恢复说明 `RESTORE.md`
- 技能文件夹快照（只作本账号当时的副本，对账以 Git 为准）
- 环境脚本、近 30 天 snapshots、用户上传的文档（按例程限制）

技能和角色的共同来源是 Git。硬盘包里的技能只是当时快照，恢复时先拉仓库，再按需看包里有没有尚未回写仓库的改动。

## 记忆不要自动对倒

记忆是各账号自己的工作记录。要看对方记了什么，打开对方子目录里最新的包，对着看，用户点头后再改自己这边。禁止两边定时互相同步记忆，也不要做自动解除冲突。

## 恢复顺序

1. 拉 Git 仓库，按 `HANDOFF.md` 装技能、按花名册建机器人。
2. 连上 Notion、Google Drive、GitHub。
3. 需要本账号的记忆和例程时，打开硬盘里该账号子目录的最新压缩包，按包内 `RESTORE.md` 贴回。
4. 跑 `qa-ready.sh`。
