# Git 与 Google Drive 备份怎么分

各 Grok Bot 账号共用同一个公开仓库和同一份 Google Drive「QA机器人备份」文件夹。备份子目录按账号名建，不写死账号名单。日常先把共用内容同步到 Git，再按账号把压缩包备份到硬盘。各账号只写自己的子目录。

## 说明放哪

这份说明放在 Git：`grokbot/BACKUP.md`。两边拉同一份仓库，规则就一致。不要只放在硬盘备份包里，免得各写各的、对不上。

硬盘包里的 `RESTORE.md` 只写「本账号怎么恢复」，并指向本文件，包括「恢复与对照同步检查清单」。不要把整份规则或整份检查清单再抄进包里当正本。

## 三处各放什么

| 放哪 | 放什么 | 谁用 |
|--------|--------|------|
| Git 仓库 qa-agent-team 的 `grokbot/` | 角色说明、花名册、共用技能的脱敏副本、协作规范、本说明、常驻规则包 | 各账号都拉、都按这个对齐 |
| Google Drive「QA机器人备份」 | 按账号分开的周备份压缩包，用来恢复「这一个 bot 账号」 | 各账号只写自己的子目录 |
| 各项目 Notion 知识库 | 业务知识、用例、缺陷、测试日志 | 不进 Git，也不进硬盘压缩包 |

密码、token、密钥、测号明文、Cookie、.env：三处都不写。查号和写回的细则见技能「测试账号云端同步」。

## 账号表怎么查、怎么写

官方是两本谷歌表。地址见同步总表与本机指针，不写进本说明。

- 「测试账号-完整库」：正表，放全部账号。
- 「测试账号-给人看」：只给人看，不作为查密文的第一来源。每域名最多 3 条，用户给的主号优先。

查账号顺序：本机优先，没有再查完整库。人给的账号写入本机和完整库，并按规则更新给人看的表。大批量生成的测试账号默认只进完整库和本机。旧表「各项目测试账号与凭证」不再作为官方查找处。

## Git 里不放什么

- 记忆正文（profile / journal 导出）
- 现网例程的提示词全文打包（例程跟账号走，进硬盘包）
- Drive 备份压缩包本身
- 凭证、表链接、Notion 页面链接、对话链接、邮箱、窗口路径

工作台对话对应关系的正本是谷歌表「QA机器人Cursor工作台」，按账号分页。地址见同步总表与本机指针。不要在仓库里另做一份映射正本，也不要把对话链接写入 Git、规则包或本说明。

两边对齐技能和职责：拉仓库，有改动就开 PR。不要用周包、增量包或 skill-sync 包覆盖仓库里的技能副本，也不要覆盖现网技能。仓库技能以现网为准，改完再回写仓库。跨账号只对照技能 id，不把对方的技能 id 写成本账号已经接上。

## 硬盘包里放什么

每个账号每周日做一次完整备份，传到：

`QA机器人备份/<账号名>/qa-backup-weekly-<账号名>-<YYYYMMDD>.zip`

账号名用这个 Grok Bot 账号当时的名字。没有同名子目录就新建。只写、只恢复自己的子目录。不改、不删其他账号的子目录，也不动根目录下其他账号的文件。对照同步要只读对方目录里的最新完整备份，并查较新的增量包或 skill-sync 包。步骤见「恢复与对照同步检查清单」。

每周日打一次完整包。打包时和上一包对比，核对校验值，写出变更记录和清单。旧包不删除，在原文件名前加 `已替换-`。失败时保留旧包并说明。

包内另放两份只读材料：规则包镜像（文件名带版本），以及一句指针「规则包正本在 Git，恢复时不覆盖」。工作台表快照同样只读，恢复时不覆盖谷歌表里更新的映射，并且不把对话链接写进 Git。

包里只放：

- 本账号能读到的记忆导出（自己的和共享的 profile / journal）
- 本账号机器人名单（名字、标题、描述和对应 json）
- 本账号例程（名字、时间、提示词）
- 本账号的恢复说明 `RESTORE.md`
- 技能文件夹快照（只作本账号当时的副本，对账以 Git 为准）
- 环境脚本、近 30 天 snapshots、用户上传的文档（按例程限制）
- 备份那一刻的交接，放在压缩包根目录。默认一份 `WORK-STATUS.md` 或 `交接.md`，含下面六项。拆成短清单时，每一份都要在这个包里

技能和角色的共同来源是 Git。硬盘包里的技能只是当时快照，恢复时先拉仓库，再按需看包里有没有尚未回写仓库的改动。不能用仓库原文直接覆盖现网技能 id。

## 备份那一刻的工作点交接

2026-11-17 用户确认。这是备份流程约定，正本在本仓库本文件，不是平台 Auto-review，也不是 AI 规则。做备份的步骤见 `grokbot/skills/account-backup/SKILL.md`。各项目知识库的每日存档走日备读回，和本节不是同一件事，不互相替代。

以后做本账号完整备份时（包括每周日的周备份，以及换号用的全量备份），必须按「备份的那一刻」写清各项目、各工作点正在做的事，并写上下面六项。默认写进同一份交接文件。拆开时，每一份都要进包。`MANIFEST.md` 和 `RESTORE.md` 都要写明这些文件的名字和在包里的位置。

交接的目的：另一边拿到备份后，马上知道已经做了什么、接下来要做什么、去哪里查看。用户让他们做事时，也能立刻找到入口。几个账号同步时要对上看、列出差异、等用户点头再改，不要自动覆盖对方已有内容。

六项都要有：

1. 已经做了什么、接下来要做什么、去哪里查看。去哪里查看包括：对应该项目这个工作点的机器人聊天入口、缺陷单、用例页、知识库入口、HTML 报告、跑次目录、本地未写库的稿、工作台映射位置（谷歌表「QA机器人Cursor工作台」里本账号那一页；做对照时连同对方账号那一页，例如「工作台-sacks」和「派单记录-sacks」，并写核对日期。地址见同步总表与本机指针）。这些地址写在周包内的交接里，不写入本说明。对话链接不写入本说明，也不写入 Git。未核验通过的旧协调器 id 不写成可用。
2. 待用户拍板的事。
3. 连接器与账号标签清单：已接哪些、哪条未授完。只写名称和状态，不写 token，不写凭证表链接。
4. 仓库未合变更与现网差异：打开的 PR、草稿 PR、现网技能版本和技能 id 与仓库的对照。必须写明：换号后只拉 main 可能漏掉未合内容；不能直接用仓库原文覆盖现网技能 id。
5. 机器人角色对照：角色名、当时 id、是否已删除。必须写明：换号后 id 会变，先按角色建号，不要按旧 id 把已删的号重建回来。
6. 进行中产物索引：见第 1 项，不另抄一套。

写法：

- 按项目分节，至少包括 T8T、M3（含支付与重粉库）、GO。nova 在花名册是暂停时，该节只写「暂停，跳过」。小程序由用户自管，总控不管，该节只写这一句。
- 每个在用项目里再按工作点写第 1 项。工作点以备份当时花名册里该项目实际有的号为准，例如需求分析、测试主管、测试执行、站点走查、提单回归、知识库总控、日报、周报，以及当时仍在用的专项号。没有在测任务的工作点写「当前无在测任务」，不要省略该工作点。M3 的支付和重粉库分开写入口和现状，不拿一套代替另一套。
- 第 1 项里把正在测什么、卡在哪、等谁、未关缺陷写进「已经做了什么」和「接下来要做什么」。六项都只写备份那一刻能核实的事实。不要用旧截图、旧结论或猜测写进度。没有当轮能核实的事实就写「未核到更新」，不要编造链接、进度、PR、技能 id 或角色 id。
- 不写密码、token、测号明文、Cookie、凭证表链接、聊天全文、`store.db`。可以写测号名称、环境、缺陷库链接、报告路径。

这份交接是给另一账号或新总控对照用的。`RESTORE.md` 要写清：对照恢复时，几个账号对上看、列出差异、等用户点头再改。不要用这份交接自动覆盖对方已有的记忆、例程、机器人资料和其他已有内容。

## 记忆不要自动对倒

记忆是各账号自己的工作记录。要看对方记了什么，打开对方子目录里最新的完整包，对着看，列出差异，用户点头后再改自己这边。最新完整包可能旧于同一目录里较新的增量包或 skill-sync 包，也可能旧于现网工作台。要看规则、技能、角色说明、协作规范和工作台时，按「恢复与对照同步检查清单」把这些来源一起读。几个账号对交接、记忆、例程和机器人资料同样处理，不要自动覆盖对方已有内容。禁止两边定时互相同步记忆，也不要做自动解除冲突。

## 用户说「同步」

同一账号日常说「同步」：把尚未回写仓库的共用改动开 PR，总控不自己合并。不跑下面的换号清单。

换到新 Grok Bot 账号或新机器后，或用户要求对照另一账号（含已标停用的 sacks）时，按固定顺序做。拉完 Git 不算同步完成。是否恢复完成，看「恢复与对照同步检查清单」。

1. 拉取公开仓库 qa-agent-team，按 `grokbot/HANDOFF.md` 安装技能，按花名册建机器人。换号后机器人 id 可能变化，不要把旧 id 当成当前号。旧账号机器人停用，也不等于该账号里已有的 Cursor 对话失效。
2. 读 `grokbot/cursor-resident/PACK.md` 首行版本，和本机指针里的已装版本比较。地址见同步总表与本机指针。版本相同则不写规则包。任何情况下都不用周包、增量包或 skill-sync 包覆盖 Git 里的规则包，也不覆盖谷歌表「QA机器人Cursor工作台」里已更新的映射，也不覆盖现网技能。
3. 重新连接 Notion、Google Drive、GitHub 等连接器。连接器授权、云电脑登录态、Cookie 不能从备份恢复，必须由用户重新点授权、重新登录。
4. 恢复本账号记忆和例程：只打开「QA机器人备份/<本账号名>」里最新的周备份包，按包内 `RESTORE.md` 贴回本账号。没有同名子目录就新建。不把对方记忆贴回本账号。不改、不删对方子目录。
5. 做对照，不在这一步恢复：按「恢复与对照同步检查清单」只读对方账号目录的最新完整备份，并查较新的增量包或 skill-sync 包。读规则、技能、角色说明、协作规范、工作台映射。再核对双方工作台页和派单记录，包括「工作台-sacks」和「派单记录-sacks」。列出差异，等用户点头再改。不自动覆盖对方已有内容，也不对倒记忆。
6. 运行云电脑上的 qa-ready.sh，不要默认跑 bootstrap 或 apt。
7. 测号不在包里、也不在 Git。查号按「测试账号云端同步」，位置见同步总表与本机指针。聊天不写密码。凭证、密钥、测号明文不进 Git，也不打进备份包。
8. 不要恢复完整聊天记录、`store.db`、附件原文。业务记忆点以各项目 Notion 知识库为准。账号记忆以周备份里本账号的记忆为准。Cursor 对话按下面的检查清单验收，入口说明见「Cursor 对话怎样同步和恢复」。验收缺清单里的任一项，结论写未完成。

## 恢复与对照同步检查清单

换号、换机器，或用户要求对照另一账号（含已标停用的 sacks）时，用这一节验收。同一账号日常只说「同步」、意思是把共用改动开 PR 时，不跑这一节。

Git 拉完不算同步完成。清单里缺一项，结论写未完成。

### 正本冲突先挂起

本清单不裁决正本。仓库里有两套说法。一套写工作台正本是谷歌表「QA机器人Cursor工作台」，Git 不另做映射正本，见本文件前文、`grokbot/cursor-resident/PACK.md` 和同步总表技能。另一套写正本是 `grokbot/workbench-map.md`，谷歌表只是同步副本，见 `grokbot/HANDOFF.md`、`grokbot/workbench-map.md`、`grokbot/skills/project-bot-collab/CURSOR-WORKBENCH.md`。两套都读。按日期和来源列出差异，等用户确认后再改认正本。不自动解除冲突，不覆盖另一账号的记忆，不改谷歌表里较新的行，不覆盖现网技能。

### 来源

1. 拉取 Git。读规则、`grokbot/skills/` 里的技能副本、`grokbot/cursor-resident/` 里的规则和技能、角色说明、协作规范、`grokbot/workbench-map.md`。这只是来源之一。
2. 读 Google Drive「QA机器人备份」里对方账号目录的最新完整备份，按包内 `RESTORE.md` 只读对照。记录包名、更新时间、账号。本账号记忆仍只从本账号目录贴回。
3. 同一目录里，比该完整包更新的增量包或 skill-sync 包也要读。完整包可能落后于这些包，也可能落后于现网工作台。
4. 从包里读规则、技能、角色说明、协作规范、工作台映射。记下源文件、更新时间、账号。技能快照只对账。跨账号技能 id 对照着写。不用仓库原文、周包或 skill-sync 包覆盖现网技能 id，也不覆盖仓库里的技能副本。
5. 凭证、密钥、测号明文、Cookie、凭证表链接不进 Git，也不打进备份包。对照清单里也不抄这些。发现就停，不上传。

### 工作台

打开谷歌表「QA机器人Cursor工作台」。地址见同步总表与本机指针。对方账号和本账号各自都要看：工作台页、派单记录页、已有 Cursor 主对话、主题或需求子对话、Project 协调器。sacks 看「工作台-sacks」和「派单记录-sacks」。本账号看自己的「工作台-账号名」和「派单记录-账号名」。

下面任一项都不能单独用来断言所有入口缺失：本账号页是空的、仓库里的旧快照、旧机器人停用标签、当前账号的 Projects 列表没有记录。机器人停用或换号后 id 会变，不等于该账号里已有的 Cursor 对话失效。Git 里 sacks 的停用空行可能旧于表和较新的包。

比对时写日期和来源，列出差异。不自动宣布正本变更。

### 三种入口

- Project 协调器。按该账号已核实的协作规则路由。共用框架、云电脑脚本、机器人协同走对应的共用协调器。业务由该项目主管对接该项目的协调器。
- 角色常驻，也就是主对话。
- 需求或主题子对话。

角色常驻和需求子对话不顶替协调器。不新建重复窗口。未经用户允许，不为尚未建立的项目新建 Project。协作细则见 `grokbot/skills/project-bot-collab/CURSOR-WORKBENCH.md`，本清单不另抄派工步骤。

用户标明暂停的范围，只核离线映射。M3（含支付）和 nova 在这类暂停范围内：不唤醒、不派工、不测试、不建工作台。花名册仍以 `grokbot/bots/roster.md` 为准，本清单不改花名册。

### 核验状态

查到映射，不等于当前账号能访问，不等于已经发送，不等于已经落地。

先只读核验现存入口。需要 JoinProject 时，必须先有用户当轮明确允许。拒绝后如实写「不存在，或当前账号没有该团队权限」，不判定是哪一种。写明未加入、未发送。等待有效的分享入口或授权。不换 id 试探，不绕过权限，不另建 Project 当替代。只有实际确认之后，才写加入成功、发送成功或设置成功。历史入口未经当前账号核验通过的，不写成已验证可用。某一次用过的旧协调器 id 不写死进仓库。

### 验收才算恢复完成

下面都要有：

1. 来源和时间对照：Git 提交、对方及本账号的最新完整包、较新的增量包或 skill-sync 包、工作台表。每项写源文件或包名、更新时间、账号。
2. 规则和技能差异清单，含跨账号技能 id 对照。没有差异写「已对照，无差异」。
3. 各号与协调器映射的核验状态：只读核到、访问阻塞，或未核到。
4. 访问阻塞。JoinProject 被拒时写「不存在或无团队权限」、未加入、未发送。
5. 未同步项。包括等用户确认的规范冲突、未覆盖的现网技能、未改的谷歌表、未对倒的其他账号记忆。

现网技能、其他账号记忆和谷歌表的改写不在这份清单的执行范围内，除非用户另有当轮授权。

## Cursor 对话怎样同步和恢复

每个机器人对应哪条 Cursor 对话，本文件原有说法是：正本是谷歌表「QA机器人Cursor工作台」，按账号分页。与 `grokbot/workbench-map.md` 不一致时，不在恢复时自动改认，见「正本冲突先挂起」。现在查、写当前号用本账号那一页。地址见同步总表与本机指针。不要在仓库里另做一份映射正本，也不要把对话链接写入 Git、规则包或本说明。

对话正文在 Cursor 后端。同一个 Cursor 账号打开映射里的原对话，就可以接着聊。这是 Cursor 自己的保存，不是周包。
