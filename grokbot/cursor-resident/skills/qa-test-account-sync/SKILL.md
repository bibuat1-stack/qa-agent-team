# 测试账号云端同步

产物是正表「测试账号-完整库」和已写入的 Notion、本地文件上的账号密码是否一致。不用于派活，不用于写业务知识库。项目暂停时仍可读写账号正本，但不因此开工。

机器人和 Cursor 都做这一套。两边不是同一台机器。当前机器没有本地文件时，直接查完整库。

## 停手

问不清项目、系统或账号别名时，只问：「要查或改的是哪个项目、哪个系统、哪个账号？」

聊天可以写测试账密。谷歌密钥、验证码、token 仍不写。用户要看测试账密时直接给出账号和密码，不改成只给页名、表名或指针。

没有用户当轮原话，不改旧表「各项目测试账号与凭证」。该旧表不再作为官方查找处。

正表和已写入处读回不一致，保持未完成，不把其中一处当成已同步。

本地和完整库都没有，当次任务又不允许创建、注册或建号，并且没有可写回的账密：停。写「本地和完整库都没有这个账号，停。」不跨项目借用，不编造密码，不叫用户去填保险库。

不把完整库里的全部账号堆进「测试账号-给人看」。

密钥类只记是否存在。禁止复制、删除、重置、改值。不要用「有」或「没有」去覆盖已填的密钥格。

## 正本

- 本地，机器人云电脑：`/workspace/qa/secrets/qa-test-accounts.md`
- 本地，那台 Windows：`C:\Users\青鸟\Documents\qa-test-accounts.md`
- 谷歌表「测试账号-完整库」，按项目分工作表。这是正表
- Notion 页「测试账号」。这是同步写入处，不是查找第一来源

查找顺序：先本地，没有再查完整库。当前机器上没有本地文件，就直接查完整库。表链接不写进本技能。

「测试账号-给人看」每域名最多 3 条，用户给的主号优先，不是查找第一来源。

本机和 Notion 用同一套列：环境、系统、域名、账号、密码、谷歌密钥、保险库登录名、用途、更新日期。环境名按本项目知识库已确认叫法写。保险库登录名只是已有列名。查找和登录不读它，也不弹保险库。

## 查找

1. 按项目、系统、环境、账号别名先在本地定位。当前机器是机器人云电脑，读上面的云电脑文件。当前机器是那台 Windows，读上面的 Windows 文件。当前机器上没有这份文件，就做第 2 步。
2. 本地没有，再查完整库对应项目表。不要只在给人看的表里查缺。不要把旧表「各项目测试账号与凭证」当官方查找处。
3. 账号、密码齐全：直接用于登录。不弹安全账号、保险库或安全表单。会推到 GitHub 的文件可以写测试账密明文。密钥类的值仍不写。
4. 没有或不全：当次任务允许时，自己创建测试号，或按允许的方式去云端找、前台注册或后台建号，然后立刻写回并读回。不允许时停。不编造密码。不叫用户去填保险库。

## 增加或更新

1. 先读正表、Notion 页「测试账号」，以及自己碰得到的本地文件，再合并。没有用户当轮原话要求删除的非空账号和密码，不准用空值覆盖。
2. 谷歌密钥以及其他密钥类不写值，不复制、不删除、不重置、不改值。已填的密钥格不要改。
3. 人给的账号：先写碰得到的本地文件，再写完整库，再写 Notion「测试账号」，再按规则更新给人看的表。
4. 大批量生成的测试账号只写碰得到的本地文件和完整库，不写入给人看的表。
5. 写谷歌表时按字面写入，避免把加号和乘方符号当成公式。
6. 写 Notion 时，测试账密按原文写入。密钥类不写值。
7. 碰不到的本地文件写明待补，不能假装已经写过。
8. 写完按原路径、原页名、原表名再读一次。比较前去掉 Notion 可能加上的转义。未转义的原文是基准。
9. 正表和已写入的 Notion、本地文件的账号、密码、用途一致，才算完成。不一致只报告哪一处哪一列对不上，不写值。读回对不上时以重读原文为准。

## 填写

项目、系统、环境、账号别名、动作（查找、新增或更新）、更新了哪些列名、是否批量生成、三处读回是否一致、给人看的表是否按规则更新、结论。测试账密可以写。密钥类只写有或没有，不写值。
