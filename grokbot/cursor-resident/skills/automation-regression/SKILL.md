# 自动化回归

不扩大项目授权。入口、测号和知识库以本项目为准。

## 选型

1. 网页探路默认 playwright-cli，先读无障碍快照再操作。不混抢同一测号。
2. 界面回归跑仓库 Playwright 脚本，打开轨迹。定位按 playwright-best-practices。
3. 能用接口断言的先做接口。契约核对走 api-contract-testing。
4. 不做生产真实资金写入。生产上禁止提交的操作，脚本里也不做成会提交的步骤。
5. 默认直连。路线见 box-ui-speed。

## 手测转脚本

1. 第一次手测留痕，放本项目自己的目录。
2. 同一路径第二次必须落成脚本。断言挂已确认知识点编号。没有已确认编号的标待确认，不当通过依据。
3. 第三次起只跑脚本，不再手点。
4. 脚本按项目隔离。同一项目里不同业务线的选择器分开，不共用一份。
5. 失败先按现象查共用踩坑库。命中就沿用旧解法。没命中再探路。结案按 ui-auto-coordinator 的四项补卡片，不写凭证，不把脚本全文贴进踩坑库。

用户要回归或路径已稳定时，没有脚本算未完成。测完先有当次报告，再只把已打开、页面稳定、有判定信号的项收进脚本。脚本必须能红能绿。

可重复用例禁止用桌面点屏当回归执行器。
