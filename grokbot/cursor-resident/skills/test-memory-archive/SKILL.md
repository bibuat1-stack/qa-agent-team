# 测试记忆-存档

只整理知识类。不出测试报告，不释放资源。用户说收工时先按批次收尾。项目暂停时不写库。

## 写库闸门

只写本项目唯一知识库。GO 入口未定不写库。地址见同步总表与本机指针。

新写知识点一律「待确认」。来源必填，至少连一条关联。没来源的不写。

已确认条目不原地改，也不在原条追加。补充或冲突另建一条待确认，关联旧条，旧条不动。给已确认条补业务线、逻辑线、上级或关联可以做；要点、状态、来源不动。一次改 10 行以上的结构回填，由总控核完后直接写。

升已确认、关闭缺陷、改成已过期、改系统地图：先列清单，只认用户当轮原话。

写完按原标题读回。读回失败不算保存。不写账号、密码、token、密钥、验证码。遇到这些写「见同步总表与本机指针」。

## 分工

测试执行只交待写清单，不直接改库。本项目知识库总控去重、写库、读回。没有知识库总控时先问用户由谁写，不自行写。用例进度不走本清单。

## 待写清单

1. 未命中：问的什么、在哪碰到、查过什么。
2. 新知识点：标题、类型、模块、业务线、逻辑线、上级、关联、来源、要点。
3. 用例正式编号和要挂的知识点编号。
4. 缺陷单号、状态、涉及的知识点。
5. 今日进度：做了什么、没做完、下一步。

## 知识库总控怎么写

先搜标题和关键词。已有待确认条可以补要点和来源。已有已确认条不改，补充另建待确认条。冲突也另建待确认条，旧条是否改已过期等用户当轮原话。

要点一句话，60 字以内。状态只能是待确认。每个新条至少连一条：改变、依赖或上级。叶子最多一个上级。一条关联都连不上的不写。

写完逐条读回。新条状态全是待确认，来源都有值，每条至少一条关联。返回里列新条编号、冲突点、无增量时写「无新知识点」、受影响用例编号。不写页面链接。
