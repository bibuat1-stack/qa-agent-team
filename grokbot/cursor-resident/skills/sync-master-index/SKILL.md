# 同步总表

只做三件事：登记出处、按类型和范围查找、由总控更新总表行。不查写账号，不打周包，不写踩坑正文，不改对话映射。

## 停手

筛完没有命中行：向当前在用账号的总控报一行（类型、名称、缺哪一类）。不猜地址，不新建第二张总表。

要改总表行，但不是当前在用账号的总控，或要改的不是自己账号的备份行、交接行：只报变更，不自己改格。

本技能和会推到 Git 的文件不写表链接、页面链接、邮箱、密文。云端地址只写在总表格子和本机指针里。

## 表

表名「同步总表」。大约十几行。九列：类型、范围、名称、正本位置、副本位置、谁读、谁写、何时更新、用法。用法限一句。

八类：账号、知识库、技能、备份、踩坑、大文件、对话/工作台、交接页。

地址见同步总表与本机指针。旧表「各项目测试账号与凭证」不进总表，也不作为查找出处。

## 正本怎么认

- 工作台正本是谷歌表「QA机器人Cursor工作台」。不要再做一份 Git 正本。只续本账号那一页。对照另一账号（含已标停用的 sacks）时仍要读对方页和派单记录，并读对方最新完整备份和较新的增量或 skill-sync 包。步骤只在 `grokbot/BACKUP.md`「恢复与对照同步检查清单」。本技能不改映射。和「正本在 `grokbot/workbench-map.md`」的说法冲突时，列出差异，等用户确认，不在这里改认。
- Cursor 执行技能以已合并的 `grokbot/cursor-resident/skills/` 为准。`grokbot/skills/` 只供对账。
- 踩坑正本是 Notion「01 共用方法」下「共用踩坑库」。
- 账号查找先本机，再查「测试账号-完整库」。
- 大文件只登记位置和用途。同步时不下载。没有确定目录名就写「待登记」，不猜名称。

## 怎么读

只有不知道正本在哪时才打开总表。筛选范围等于「共用」或本项目或本账号，并且类型等于当前这一类。只读命中行的名称、正本位置、用法，然后关掉表。

不读整表，不把行抄进记忆或对话。

## 谁可改行

当前在用账号的总控改共用行。备份行和交接行由该账号总控改自己的。其他执行者只读。

出处、谁写或用法变了才改行。库里的内容变了，不改总表行。

## 踩坑去重

可复用踩坑或已验证解法，当时写入共用踩坑库。先按外发规则去掉凭证。一次性业务规则回该项目知识库。

现象指纹等于类型加范围加对象加一句现象，不含日期、账号、对话。

1. 先按指纹检索。
2. 命中未解决：在原条追加本次已尝试，不新开。
3. 命中已验证解法且本次仍有效：不新开，回报里写原标题。
4. 命中已验证解法但本次无效：新开未解决条并写关联，原条不动。
5. 无命中才新开，新条默认待验证。
6. 写完按原标题读回。同指纹两条时，保留更早的一条，后条标「并入」。

已验证解法的正文只许原写入者或当前在用账号的总控把状态改成「被替代」。不删原文。
