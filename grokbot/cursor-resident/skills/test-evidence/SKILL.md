# 测试证据

先有证据，再说做完。通过标准只以本技能为准。开工和收尾只指向这里，不另定判定。

## 不在这里做

- 开工三步、出报告和释放资源：分别走开工三步、批次收尾。
- 外发前的密钥类处理：走 evidence-hygiene。测试账密可以留在本机留痕、当次报告、结论包、仓库、聊天和知识库正文。

## 铁规

1. 没有对得上当前范围、版本、环境的证据，不准说通过、做好了、修好了、没问题、都对上了。
2. 执行人自己的报告不算独立核验。
3. 没改且上次核验仍然有效的部分可以沿用。用户当轮要求回归、复验或重新测试时，必须进入当前要测的环境，重新登录，当场重跑并留下这次的新证据。旧截图和旧结论只可对照，不能充当这次已经测过。没有当轮新证据，不得写通过或失败。证据图上传到 Notion。不能只在结论里写机器人电脑上的本地路径。
4. 只报进度时不触发全套重验。证据撑不住，就照实报现状。

## 写通过之前

证据路径非空，评审状态是已放行，依据更新时间不晚于最近执行。高风险还要签字已签。缺一项写已跑待评审或已跑待确认，不算通过。

## 判定

结论只许：通过、失败、阻塞、未测、未验证。批次进行中还可以写已跑待评审、已跑待确认，这两项不算通过。

1. 结论只来自当次看到的证据：截图、请求响应、控制台、日志或页面状态。不用「按理说应该」。卡住先分清是站点问题、脚本问题还是环境问题。卡住本身不直接判失败。不受影响的测试项继续测。
2. 步骤能跑完就记失败加证据。阻塞只用于缺权限、缺数据或环境不可用，并写清已试过的替代路径。
3. 每条先定判定信号。中途换成更弱的判定，结论标部分验证并写明原因。
4. 报缺陷前先排除测量工具误判、有意设计、改动前基线、以及不属于本次范围。过不了的写成观察，不报缺陷。
5. 反例必须配同条件正例。正例失败时，反例结论作废。
6. 意外结果先核对工具和环境，再怀疑产品。mock 只验证应用反应，不验证塞进 stub 的文案。用完要证明 mock 已去掉。
7. 预期来自需求、已确认知识点或原型，不来自当前实现。冲突记失败或待确认。
8. 列表、排序、筛选：先等对应接口返回，核对参数、状态和首行，再截图。用接口逐行比对单元格，不按表头位置目测。异常至少复现两次，两次都错才判失败，只出现一次写待复现。没核到的方向写未验证。

## 留痕

每批至少记：起止时间、范围、通过标准、通过失败阻塞未测的数量、失败摘要、证据路径，以及直连还是代理、无头还是有头、用的哪种工具。

要记的还有：页面路由或菜单路径、关键步骤、稳定定位（role、可访问名、data-testid，最后才是坐标）、接口方法路径状态码和关键字段、预期依据、实际结果、环境、账号别名、时间及所在时区。

本机留痕、当次报告和结论包按原文保存，登录字段和测试账密可以写入本项目留痕，方便复现和写脚本。报告标题不要写「已脱敏」。仓库、聊天、Notion 知识库正文都可以写测试账密。密钥类、验证码、token 仍不写。外发材料里的密钥类仍不写。

先复用已有 API 或 UI 脚本，跑固定流程。卡点单独用页面操作现取证。修好之后，把能复用的步骤补回脚本。一批测完，出一份带原图的 HTML 报告。自动化结果和人工复核写进同一份。

账号周备份包可以不重复打包测试账密（云端和仓库已有即可）。密钥类不打进周备份包。

## 清理

删除以一条留痕或一个用例目录为单位，不整树清空。删之前四项都要过：允许同步的部分已读回，或已写明只登记位置；没有未关缺陷和待复验；已转成脚本并读回，或自留痕日期超过 7 天且没有未关项；测试日志已写下清理了哪一条。缺一项不删。结论包和报告当天不删。
