# 测试记忆-影响面

只读。看不出改了什么先问。只认本项目唯一知识库。GO 入口未定就停。不进别的项目库。

补测建议的预期只引用已确认知识点的编号和要点原句。待确认和可能过期只作背景。标题带【示例】的不当预期。拿不出依据写「知识库里没有」，记入未命中清单。

没有业务线或逻辑线属性时按模块分组，跳过对照，并写明已跳过。

## 步骤

1. 定起点：找出改动直接碰到的知识点。没有就写「知识库里没有」。
2. 第一圈：起点改变的对象和配置、依赖起点的知识点、起点的下级。
3. 第二圈：对这些对象再找被改变、被依赖的知识点。到第二圈为止。
4. 走到对接桩就停，不进对方库。该行写「需对方库评估」。
5. 同一对象被两个以上功能改变时，看结果是否矛盾、顺序反过来会怎样、同时发生会怎样。
6. 圈内没有覆盖用例的标「缺用例」。相关缺陷不为空的标「出过问题」。
7. 同逻辑线、但不在圈内业务线的已确认知识点，最多 5 条，只作提问线索。
8. 对圈内每条逻辑线，按测试记忆-体检的必问清单逐项三选一：已确认编号、待确认编号、知识库里没有。

## 返回

起点；按业务线分组的影响清单；冲突和并发风险；已有用例编号；补测建议，预期没有已确认依据就写「知识库里没有，停」；同逻辑线对照；必问清单结果；未命中清单。要把建议写成用例时交给测试记忆-存档。
