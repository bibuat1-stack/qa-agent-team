# 测试记忆-建库

给新项目建知识库。需要项目名、模块列表、父页面。缺哪个就问。已有库不要重建，只补缺的属性和视图。

地址见同步总表与本机指针。账号密码不进库。

## 顺序

关联等目标库建好再加。自关联等知识点库建好再加。

1. 父页面下建首页「项目名 · 测试知识库」。正文写明：先读系统地图，再按模块查知识点；写知识点必须连关联；账号密码不进库。
2. 首页下建系统地图，四节：模块、核心业务对象、耦合热点、待确认。不知道的写待补。
3. 依次建六个库：资料索引、知识点、测试用例、缺陷、测试日志、执行记录。
4. 加关联，最后加公式和视图。

## 库

每个库的模块都是多选，选项用模块列表加「通用」。

资料索引：名称、类型、模块、链接、版本或日期。链接写在库页面里，不写进会推到 Git 的文件。

知识点：标题、手工文本编号、类型（功能、业务对象、规则、配置、接口事件、坑点、决策）、模块、要点、状态（已确认、待确认、已过期）、来源、最后核实。自关联三组：上级与下级、改变与被改变、依赖与被依赖。另有替代条目，以及和资料索引的来源资料关联。

测试用例：正式编号、临时编号、需求编号、模块、标题、优先级、风险、用例类型（日常、需求）、步骤要点、预期、依据编号、依据更新时间、覆盖、评审状态、签字、最近结果、实际结果、证据路径、撰写人、执行人、最近执行、执行次数、待确认问题、产品答复、来源需求、纳入回归、备注、归档日期。撰写人与执行人分开。新建或改未放行正文时必填撰写人。机器人写就写该机器人名，Cursor 工作台写就写「Cursor」。不要只为补这个字段去改已放行正文。已有用例不批量回填，除非用户再说。最近结果词表与测试证据一致：未测、进行中、失败、阻塞、已跑待评审、已跑待确认、通过。

缺陷：标题、单号、模块、严重程度、状态、耦合类型。复现步骤写正文。

测试日志：标题用日期，正文五节：做了什么、发现、知识变更、没做完、下一步。

执行记录：记录键用「正式编号|执行时间」，关联用例，结果词表与最近结果相同。

## 视图

知识点：耦合热点、待确认、最近更新。缺陷：未关闭、跨模块。用例：同步-日常、同步-测试中、同步-已归档。建得了就建。写完按库名读回，缺哪个库或哪条关联就保持未完成。
