# 诊断缺陷

没有能打红的反馈环，不许进入猜因。跳过阶段必须写明理由。只在本项目授权环境动手。

外发命令和产物先按 evidence-hygiene 处理。本机留痕可以留原文。Grok Bot 聊天不写明文凭证。

## 建立反馈环

找到一条自己跑过的命令或用例，能稳定打出描述的那个症状。

优先：失败用例，再是接口调用，再是对比输出，再是 playwright-cli 看页面、控制台和网络，再是回放已有轨迹。偶发问题先提高复现率。又慢又不稳定的环等于没有环。

完成标准：至少亲自跑过一次，断言的是那个症状，并且可以再跑一次。

## 然后

把输入和步骤缩到仍然失败的最小集合。一次只改一个假设。假设被证伪就丢掉，不叠加。

定位到原因就停，写出原因、证据位置、还没证明什么。不在本技能里改产品代码。测试写错了交给 e2e-debugger，并且只改测试、不削弱断言。
