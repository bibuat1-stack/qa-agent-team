# grokbot

给各项目 Grok Bot 与 Cursor Cloud Agent 用的共用技能备份、升级技能与约定说明。这里不设四角色流水线。

## 分工（2026-11-10）

| 存哪儿 | 放什么 |
|--------|--------|
| **Notion（各项目知识库）** | 业务上下文、记忆点、知识点、缺陷、进度。各项目机器人开工主读这里。 |
| **本仓库 GitHub** | 共用技能副本、Cursor 专家升级技能、稳定协作规范。可版本恢复，给 Cloud Agent 与项目机器人读。 |

凭证、token、Cookie、测号密码：**两边都不写**。

四角色流水线（需求分析师、自动化工程师、回归执行员、失败分诊员）已于 2026-11-10 停用，职责文件已删除。它们与各项目既有的主管、执行、拆分、回归重叠。不要恢复，不要按这些名字组队。

## 目录

- `bots/`：只保留「Cursor专家升级」技能原文（`0-技能-Cursor专家升级.md`），供项目机器人粘贴或对照。不再放四角色职责。
- `skills/`：Grok 共用技能的脱敏备份（`SKILL.md`）。以机器人侧 UpdateSkill 为准时，这里做可恢复副本。
- 不设 `memory/` 流水库：项目记忆点继续写 Notion。

## 使用

1. 业务任务：总控分派后，由该项目机器人查本项目 Notion 知识库并执行。
2. 写/改自动化：遵守仓库根 `AGENTS.md` 与 `.cursor/skills/`。
3. 遇自动化卡点：在 **qa-agent-team** 仓库下开 Cloud Agent（Ask / Plan / Debug / Multitask，不要 No Repo），经 `tools/ask_cursor.py` 升级。一问题一案例一 Agent 一 PR。不合并 PR，不私自改业务产品代码。
4. 自动化踩坑知识库只收集脱敏问题与解法，不探路、不写脚本、不连跑。
5. 同步技能：改完 Grok 技能后，把对应 `SKILL.md` 更新进本目录并开 PR。只含技能备份（可带本 README 或 `AGENTS.md` 里对应的一两句说明）时，CI 通过后由 Cloud Agent 自行合并进 main。

## 项目隔离

GO / nova / T8T / M3 等知识与授权严格隔离。本目录只放跨项目共用的技能与红线，不写具体业务账号与环境秘密。
