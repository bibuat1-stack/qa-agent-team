这是备份流程约定，正本在仓库 `grokbot/BACKUP.md`。本文件只写步骤。它不是平台 Auto-review，也不是 AI 规则。

本技能管本账号的完整备份，包括周备份和换号用的全量备份。各项目知识库的每日存档走日备读回，和本技能不是同一件事，不互相替代。共享资料快照的清单字段和三遍对照在 `grokbot/BACKUP.md`「共享资料快照」，这里不另抄。

交接的目的：另一边拿到备份后，马上知道已经做了什么、接下来要做什么、去哪里查看。用户让他们做事时，也能立刻找到入口。几个账号同步时要对上看、列出差异、等用户点头再改，不要自动覆盖对方已有内容。

## 停手
1. 旧周包改名留着、不删除。测试登录账密不进周包，也不进共享快照。不要为了去掉账密去删已经留着的旧记忆包。
2. 密钥类、token、Cookie、凭证表链接、聊天全文或 `store.db` 的正文要进这一份新包：从新包里拿掉再打包。密钥类只记有没有。拿不掉就停，不上传。不删除已经留着的旧周包。
3. 某一项没有当轮能核实的事实：写「未核到更新」。不用旧截图、旧结论或猜测填进度，不编造聊天入口、单链接、报告路径、PR、技能 id 或角色 id。
4. 不改、不删另一个账号的子目录，也不删 Drive 上其他账号的文件，也不删共享快照。旧周包只在原文件名前加 `已替换-`，不删除。
5. 记忆、例程和机器人资料对上看之后，先列出差异，等用户点头再改。不用交接或包内材料自动覆盖对方已有内容。备份包不覆盖仓库技能和现网技能。当前账号工作台核实缺失后的补齐不套用这句等待，见 `grokbot/BACKUP.md`「恢复与同步检查清单」。
6. 未核验通过的旧协调器 id 写成当前可用：改成「未核验」，或删掉该句。不把某一次的旧 id 写死成可用入口。测试登录账密不写进包。密钥类不写值。

## 谁来做
本账号总控，在做周备份或换号全量备份时做账号周包。各项目机器人不各自打这份包。共享资料快照只由 Faker 总控在周日周备份时打，别的账号不打第二份。

## 步骤
1. 按 `grokbot/BACKUP.md`「硬盘包里放什么」收集：本账号记忆导出、机器人花名册、例程、技能文件夹快照、环境脚本。恢复说明、近 30 天 snapshots、用户上传的文档仍按该节，不在这里另列一套。另写很短的 `SOURCES.txt`，只写本周共享快照的文件名、日期和清单校验。不写产品正文，不写别的账号的记忆。旧周包改名留着、不删除，在原文件名前加 `已替换-`。
2. 按备份的那一刻写交接，默认放在压缩包根目录的一份文件里，文件名用 `WORK-STATUS.md` 或 `交接.md`。可以再拆很短的清单文件，但每一份都要进包。在 `MANIFEST.md` 和 `RESTORE.md` 里写明每个文件的名字和位置，包括 `SOURCES.txt`。
3. 交接按项目分节，至少 T8T、M3（含支付与重粉库）、GO。nova 在花名册是暂停时，该节只写「暂停，跳过」。小程序由用户自管，总控不管，该节只写这一句。每个在用项目里，按花名册当时实际有的工作点各写一小节，例如需求分析、测试主管、测试执行、站点走查、提单回归、知识库总控、日报、周报，以及当时仍在用的专项号。不要省略工作点。没有在测任务的工作点写「当前无在测任务」。
4. 同一份交接（或拆开的短清单）里，下面六项都要有：
   1. 已经做了什么、接下来要做什么、去哪里查看。去哪里查看写：该工作点的机器人聊天入口、缺陷单、用例页的完整原始链接、知识库入口、HTML 报告、跑次目录、本地未写库的稿、工作台映射位置（`工作台-<当前账号>`和`派单记录-<当前账号>`；这次有来源账号时写上来源页，并写核对日期和来源。账号名不写死）。正在测什么、卡在哪、等谁、未关缺陷写进前两句。M3 的支付和重粉库分开写。暂停的项目只写离线映射，不唤醒、不派工、不测试。
   2. 待用户拍板的事。
   3. 连接器与账号标签清单：已接哪些、哪条未授完。只写名称和状态。
   4. 仓库未合变更与现网差异：打开的 PR、草稿 PR、现网技能版本和技能 id 与仓库的对照。写明：换号后只拉 main 可能漏掉未合内容；不能直接用仓库原文覆盖现网技能 id。
   5. 机器人角色对照：角色名、当时 id、是否已删除。写明：换号后 id 会变，先按角色建号，不要按旧 id 把已删的号重建回来。
   6. 进行中产物索引：见第 1 项，不另抄一套。
   没打开核对的项写「未核到更新」。
5. 测试登录账密不进周包，也不进共享快照。不写 token、密钥类的值、Cookie、凭证表链接、聊天全文、`store.db`。密钥类只记有没有，正文不进包。可以写测号名称、环境、缺陷库链接、报告路径。
6. `RESTORE.md` 只写本账号怎么恢复，并指向 `grokbot/BACKUP.md`「恢复与同步检查清单」。包内不另抄整份清单。写明：记忆、例程和机器人资料对上看、列出差异、等用户点头再改，不自动覆盖。当前账号逐个核对自己的工作台，核实缺失的补上并读回，不套用这句等待。记忆不自动对倒。备份包不覆盖仓库技能和现网技能。恢复验收要有来源和时间、规则和技能差异、每个当前机器人的核验、已补项、读回、访问阻塞。缺一项就写未完成。不要写 Git 拉完或找到来源映射即同步完成。
7. 打包上传到 Google Drive「QA机器人备份」下本账号子目录，文件名按 `BACKUP.md`。上传后核对交接文件和 `SOURCES.txt` 在包里，且 `MANIFEST.md`、`RESTORE.md` 点到了每一份。不要把共享资料快照放进这个子目录。
8. 共享快照另打，不放进本账号周包。只由 Faker 总控在周日例程已经要求打两份包时，按 `grokbot/BACKUP.md`「共享资料快照」「清单」「三遍对照」打 `qa-sources-<YYYYMMDD>.zip`，放到「QA项目资料」下的快照夹。不要放进 `QA机器人备份/Faker/`。别的账号不打第二份。例程还没改之前，不提前打。清单字段和三遍对照不在这里另抄。

- 交接文件名：（WORK-STATUS.md / 交接.md；若拆分，列出全部文件名）
- 六项是否都有：是 / 否，缺（）
- 各工作点：有在测任务 / 当前无在测任务 / 未核到更新
- `SOURCES.txt`：已写入文件名、日期、清单校验 / 未核到
- 测试登录账密进了周包或共享快照：否
- 密钥正文、聊天全文、store.db：无 / 已从这一份新包拿掉（未删除旧周包）
- 旧周包改名留着、未删除：是 / 否
- 结论：已完成 / 未完成，停因：（）
