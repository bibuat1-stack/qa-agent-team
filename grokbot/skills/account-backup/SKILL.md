这是备份流程约定，正本在仓库 `grokbot/BACKUP.md` 的「备份那一刻的工作点交接」。本文件只写步骤。它不是平台 Auto-review，也不是 AI 规则。

本技能管本账号的完整备份，包括周备份和换号用的全量备份。各项目知识库的每日存档走日备读回，和本技能不是同一件事，不互相替代。

交接的目的：另一边拿到备份后，马上知道已经做了什么、接下来要做什么、去哪里查看。用户让他们做事时，也能立刻找到入口。几个账号同步时要对上看、列出差异、等用户点头再改，不要自动覆盖对方已有内容。

## 停手
1. 包里出现密码、token、测号明文、Cookie、凭证表链接、聊天全文或 `store.db`：先删掉再打包。删不掉就停，不上传。
2. 某一项没有当轮能核实的事实：写「未核到更新」。不用旧截图、旧结论或猜测填进度，不编造聊天入口、单链接、报告路径、PR、技能 id 或角色 id。
3. 只清理本账号子目录里的旧包。不删另一个账号的子目录，也不删 Drive 根目录下对方的文件。
4. 几个账号对上看之后，先列出差异，等用户点头再改。不用交接或包内材料自动覆盖对方已有的记忆、例程、机器人资料和其他已有内容。

## 谁来做
本账号总控，在做周备份或换号全量备份时做。各项目机器人不各自打这份包。

## 步骤
1. 按 `grokbot/BACKUP.md`「硬盘包里放什么」收集：本账号记忆导出、机器人花名册、例程、技能文件夹快照、环境脚本。恢复说明、近 30 天 snapshots、用户上传的文档仍按该节，不在这里另列一套。只清理本账号子目录里的旧包，只留自己最新一份。
2. 按备份的那一刻写交接，默认放在压缩包根目录的一份文件里，文件名用 `WORK-STATUS.md` 或 `交接.md`。可以再拆很短的清单文件，但每一份都要进包。在 `MANIFEST.md` 和 `RESTORE.md` 里写明每个文件的名字和位置。
3. 交接按项目分节，至少 T8T、M3（含支付与重粉库）、GO。nova 在花名册是暂停时，该节只写「暂停，跳过」。小程序由用户自管，总控不管，该节只写这一句。每个在用项目里，按花名册当时实际有的工作点各写一小节，例如需求分析、测试主管、测试执行、站点走查、提单回归、知识库总控、日报、周报，以及当时仍在用的专项号。不要省略工作点。没有在测任务的工作点写「当前无在测任务」。
4. 同一份交接（或拆开的短清单）里，下面六项都要有：
   1. 已经做了什么、接下来要做什么、去哪里查看。去哪里查看写：该工作点的机器人聊天入口、缺陷单、用例页的完整原始链接、知识库入口、HTML 报告、跑次目录、本地未写库的稿、工作台映射位置（`grokbot/workbench-map.md` 里当时核对到的账号页）。正在测什么、卡在哪、等谁、未关缺陷写进前两句。M3 的支付和重粉库分开写。
   2. 待用户拍板的事。
   3. 连接器与账号标签清单：已接哪些、哪条未授完。只写名称和状态。
   4. 仓库未合变更与现网差异：打开的 PR、草稿 PR、现网技能版本和技能 id 与仓库的对照。写明：换号后只拉 main 可能漏掉未合内容；不能直接用仓库原文覆盖现网技能 id。
   5. 机器人角色对照：角色名、当时 id、是否已删除。写明：换号后 id 会变，先按角色建号，不要按旧 id 把已删的号重建回来。
   6. 进行中产物索引：见第 1 项，不另抄一套。
   没打开核对的项写「未核到更新」。
5. 不写密码、token、测号明文、Cookie、凭证表链接、聊天全文、`store.db`。可以写测号名称、环境、缺陷库链接、报告路径。
6. `RESTORE.md` 写明：这份交接给另一账号或新总控对照。几个账号对上看、列出差异、等用户点头再改。不要自动覆盖对方已有内容。记忆不自动对倒。
7. 打包上传到 Google Drive「QA机器人备份」下本账号子目录，文件名按 `BACKUP.md`。上传后核对交接文件在包里，且 `MANIFEST.md`、`RESTORE.md` 点到了每一份。
