# 画布页面识图测试

通用约定，不扩大项目授权，不跨项目借账号、借基准图。普通 DOM 页面不用这份，按 ui-interaction-kit 先读结构树。

## 先判断是不是画布页
1. 用 Playwright 读页面结构树（aria snapshot）。目标区域只有一个 `canvas` 或 iframe 里只有 canvas，读不到按钮名字，才按本技能走。
2. 同一页面常常是外壳 DOM 加内层画布。外壳的按钮、弹窗、输入框仍按结构树定位，只有画布里的东西才用下面的办法。

## 定位与断言的优先顺序（从稳到不稳）
1. **数据源断言。** 余额、下注、开奖、倒计时等画面上的数，先找接口响应或 WebSocket 帧（按协作技能，有实时推送时才做帧留痕）。结论以数据为准，画面只用来确认显示一致。
2. **测试钩子。** 问开发测试环境能不能导出引擎场景树或暴露 `window` 上的调试对象（如节点名、坐标、状态）。有就按普通页面定位，问到的结果记进本项目知识库，标待确认。不自己注入脚本改游戏状态。
3. **固定坐标加热区表。** 固定视口大小、缩放（deviceScaleFactor）、语言和时区，同一项目每次一致。按钮用「相对画布左上角的比例坐标」记，不记屏幕绝对坐标。点击前先截该区域确认长得对，再点。
4. **小图比对（模板匹配）。** 事先截好按钮、图标的小图当模板，用 OpenCV `matchTemplate` 在区域截图里找，阈值从 0.9 起调，记下实际得分。找不到就报失败加截图，不降阈值硬过。
5. **截图对比。** 回归时用 Playwright `toHaveScreenshot` 或像素差比对基准图，掩盖（mask）时间、余额、动画等会变的区域。只有差异区域再交 AI 看。
6. **AI 看整图。** 最后兜底。给 AI 的图先画网格或标号，让它回答格子或编号，不让它报像素坐标。AI 看图的结论只算「疑似」，要有 1～5 中任一项佐证才写通过或失败。

## 截图要求
- 等画面稳定再截：等加载遮罩消失、等指定帧数或连续两次截图差异很小，不只靠固定 sleep。
- 只截要看的区域（clip 或元素截图），图小、看得准、省 token。
- 白屏、灰屏、半截图先怀疑没等够或走了代理，如实报，不重试成「通过」。
- 默认无头加页面截图，不开平台桌面 Chrome；要用户看着或接手时才有头，开工前提醒用户。

## 留痕
- 每次点击记：热区名、比例坐标、点击前后区域截图、模板匹配得分或截图对比差异值。放本批次目录。
- 基准图和模板小图放本项目目录，文件名带视口尺寸和日期。改版后旧基准不覆盖，另存新版并在知识库写明替换原因。

## 不做
- 不改游戏前端代码、不注入脚本改状态、不改平台 Chrome 配置。
- 不把 AI 识图结果当预期依据，预期仍以需求、知识点、原型为准。
- 资金、下注类写操作按项目授权和测试账号走，不在现网真钱账号上点。

## 各项目逐步补充（每个项目一节，只写本项目）
按下面格式补，经验证的写「已验证」，没验证的写「待确认」。踩坑脱敏后交「自动化踩坑知识库」。

```
### 项目名
- 视口：宽×高，缩放，语言，时区
- 画布入口：页面路径，canvas 所在层级
- 数据源：哪些数看哪个接口或推送
- 测试钩子：有/无，问过谁，结论
- 热区表：热区名｜比例坐标｜模板小图路径｜阈值｜状态
- 基准图目录：路径
- 已知坑：现象｜解法｜状态
```
