# Cursor 工作台

本文件只补工作台规范。开工、证据、故障闭环仍以同目录 `SKILL.md` 为准。

现网协作技能正文比本仓库的 `SKILL.md` 备份新。本轮只加工作台规则。不要用仓库里的旧 `SKILL.md` 覆盖现网技能。

工作台映射正本是 `grokbot/workbench-map.md`。对话地址和对话 id 写在这份正本里，可以进 Git。谷歌表「QA机器人Cursor工作台」只是同步副本。谷歌硬盘只保存全量压缩包。日常先把映射同步到 Git，再把压缩包备份到硬盘。正本和本文件不写密码、token、密钥、测号、凭证表链接，也不写入压缩包或记忆正文。本文件不另抄对话地址。

按 Grok Bot 账号分页，不要把不同账号叠在同一张表里。每个账号用自己的「工作台-账号名」和「派单记录-账号名」。查表先打开对应账号那一页。现在在用的是「工作台-Faker」和「派单记录-Faker」。「工作台-sacks」只作历史对照，不得续聊，那些稳定 id 不要当成当前号。Faker 的常驻行已经登记。自动化踩坑知识库已是「在用」。其余常驻行对话列为空，状态为「空」。GO电子是壳号，不建工作台。小程序不进本表。

## 两条通道

工作台给思考、方案、代码草稿。默认模型是 Grok 4.7。

映射里有两种行：

- 常驻：一个在用项目号一条。需求标识留空。同类活续聊。
- 需求分析：一条需求一条对话，走该项目需求分析机器人的工作台。需求标识必填。不把多条需求续进同一条对话。同时处于「在用」的需求分析对话最多 5 条。

不预建空的需求分析行。没有第一笔思考、方案或代码活，不建对话。Faker 的常驻行可以先占着。还没开过对话的，对话列保持空，状态保持「空」。自动化踩坑知识库已是「在用」，同类活续聊。新开账号先写入账号对照，再新建「工作台-账号名」和「派单记录-账号名」。不同账号不要写进同一页。

升级走常驻 Ask、Plan、Debug、Multitask，再加上 `tools/ask_cursor.py`。一事一案，一个 Agent，一个 PR。这四个席位不是映射里的常驻行，不按机器人再复制。

分流：

- 思考、方案、代码草稿走该机器人自己的工作台对话。不跑 `ask_cursor.py prepare`。不占升级每日额度。
- 只有要改共享框架并开 PR 时，才走升级技能的 prepare / fix。
- 工作台不替代常驻 Ask、Plan、Debug、Multitask。
- 工作台不替代升级。

## 映射状态

状态只用这四个字：在用、空、停用、暂停。

先占行、后补对话时，对话列先空，状态写「空」。第一次真有思考、方案或代码活，才建对话，状态改为「在用」。

日报、走查只出报告，则不建工作台。周报同样：无思考或代码活，不建。

nova 为暂停。先不建工作台。不派活。暂停号如果已有行，状态写「暂停」。

## 何时新开

同一账号、同一机器人、同一项目的常驻对话必须续聊。只有三种情况可在原行新开对话：

1. 对话打不开、过期，或无法继续。
2. 已串项目或串了别的需求，或同一问连续两次答非所问。
3. 新启用的非暂停号，且有第一笔思考、方案或代码活。

在原行新开前，总控把旧 URL 写入「上一条 URL」，旧状态改停用，再把新地址写回原行。没有旧地址时，「上一条 URL」留空。

另一条需求是新的需求分析行，不占用旧需求那一行。

关闭需求分析对话要四项都有：需求标识；用例库标题和读回；知识库标题和读回，或写「无新增」；待确认已标明或写「无」。当天读回一致就关。分析中、没写回、读回不一致，不关。过期对话要迁移，不当成已回收。

## 简报必填

每笔简报都要有这些项：

- 账号（对应哪一页）
- 项目
- 任务一句
- 依据。没有依据就写「无依据，停」，并且不发。
- 禁做
- 已完成与证据位置
- 交付物和交齐标准
- 模型：Grok 4.7
- 续聊：是

禁做固定为：不点页面，不跑业务测试，不写测试结论，不写凭证，不开 PR，不合并 PR。

## 拿回之后

机器人自己核。Cursor 说通过不算通过。不把草稿当测过。

给用户的回答要精简。先说结论。转述 Cursor 结果同样要短。汇报不含凭证。不合并 PR。

点页面、跑脚本、取证、写测试报告，仍由机器人自己做。

## 谁写映射

总控独占写 `grokbot/workbench-map.md`，并提交到本仓库。

派单记录写在对应账号的「派单记录-账号名」。现在写「派单记录-Faker」。列是：日期、项目、机器人、续聊或新建、任务一句、对话 URL、核验结果。

工作台不占升级每日额度。
