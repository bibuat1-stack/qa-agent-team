# Cursor 工作台

本文件只补工作台规范。开工、证据、故障闭环仍以同目录 `SKILL.md` 为准。

现网协作技能正文比本仓库的 `SKILL.md` 备份新。本轮只加工作台规则。不要用仓库里的旧 `SKILL.md` 覆盖现网技能。

Git 和本文件不写对话 id、对话 URL、工作台表 id 或表 URL。表链接由用户或总控单独给。

## 两条通道

工作台给思考、方案、代码草稿。默认模型是 Grok 4.7。每个在用项目号一条对话。同类活续聊。不提前建满。

升级走常驻 Ask、Plan、Debug、Multitask，再加上 `tools/ask_cursor.py`。一事一案，一个 Agent，一个 PR。

分流：

- 思考、方案、代码草稿走该机器人自己的工作台对话。不跑 `ask_cursor.py prepare`。不占升级每日额度。
- 只有要改共享框架并开 PR 时，才走升级技能的 prepare / fix。
- 工作台不替代常驻 Ask、Plan、Debug、Multitask。不按机器人再复制这四个席位。
- 工作台不替代升级。

机器人与对话的映射只在 Google Drive 表「QA机器人Cursor工作台」。

## 表状态

状态只用这四个字：在用、空、停用、暂停。

登记时，对话列先空。第一次真有思考、方案或代码活，才建对话。

日报、走查只出报告，则不建工作台。周报同样：无思考或代码活，不建。

nova 为暂停。先不建工作台。不派活。

## 何时新开

只有三种情况可新开对话：

1. 对话打不开、过期，或无法继续。
2. 已串项目，或同一问连续两次答非所问。
3. 新启用的非 nova 号，且有第一笔思考、方案或代码活。

新开前，总控把旧 URL 写入「上一条 URL」。旧行改停用。

## 简报必填

每笔简报都要有这些项：

- 项目
- 任务一句
- 依据。没有依据就写「无依据，停」，并且不发。
- 禁做
- 已完成与证据位置
- 交付物和交齐标准
- 模型：Grok 4.7
- 续聊：是

禁做固定为：不点页面，不跑业务测试，不写测试结论，不写凭证，不开 PR，不合并 PR。

## 拿回之后

机器人自己核。Cursor 说通过不算通过。不把草稿当测过。

给用户的回答要精简。先说结论。转述 Cursor 结果同样要短。汇报不含凭证。不合并 PR。

点页面、跑脚本、取证、写测试报告，仍由机器人自己做。

## 谁写表

总控独占写表。

派单记录页每笔一行。列是：日期、项目、机器人、续聊或新建、任务一句、核验结果。

工作台不占升级每日额度。
