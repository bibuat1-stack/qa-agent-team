# Cursor 工作台

本文件只补工作台规范。开工、证据、故障闭环仍以同目录 `SKILL.md` 为准。

现网协作技能正文比本仓库的 `SKILL.md` 备份新。本轮只加工作台规则。不要用仓库里的旧 `SKILL.md` 覆盖现网技能。

本文件原有说法：工作台映射正本是 `grokbot/workbench-map.md`。对话地址和对话 id 写在这份映射里，可以进 Git。谷歌表「QA机器人Cursor工作台」只是同步副本。与 `grokbot/BACKUP.md`「正本在表」不一致时，不在这里改认，见该文件「正本冲突先挂起」。谷歌硬盘只保存全量压缩包。日常先把映射同步到 Git，再把压缩包备份到硬盘。映射和本文件不写密码、token、密钥、测号、凭证表链接，也不写入压缩包或记忆正文。本文件不另抄对话地址。

按 Grok Bot 账号分页，不要把不同账号叠在同一张表里。每个账号用自己的`工作台-<账号名>`和`派单记录-<账号名>`。查、写进当前账号自己的页。同步时用来源账号的页对照，方向不写死。来源账号的稳定 id 不要当成当前号。停用或空行也不等于那些 Cursor 对话失效。不把来源账号的对话拿来当当前号续聊。映射里的账号名只是例子。映射有「归属 Project」列。在用号的常驻工作台按花名册预建到对应 Project。需求分析不预建。日报、走查、周报只出报告，不建工作台。壳号和暂停号不建。GO电子是壳号，不建工作台。小程序不进本表。已登记的对话以 `grokbot/workbench-map.md` 为准，不要给没有登记的行编造对话。本文件不另抄对话地址。

## 三种入口

Project 协调器、角色常驻（主对话）、需求或主题子对话是三种入口。按该账号已核实的协作规则路由。

- 共用框架、云电脑脚本、机器人协同走对应的共用协调器。
- 业务由该项目主管对接该项目的协调器。
- 角色常驻是该角色自己的续聊入口。需求或主题子对话是一条需求或一个主题一条。

角色常驻和需求子对话不顶替协调器。能复用原来的工作台就复用，并补上缺的映射。窗口已经在、映射缺了，就补映射，不另开。确实还没有，并且现有规则要求这个角色有工作台，才按规则建立正确类型，登记并读回。现有规则不要求工作台的角色不硬建。不批量重建。不把来源账号的机器人 id 抄过来冒充当前号。不靠新开一个窗口来代替进不去的那个。

查到映射，不等于当前账号能访问，不等于已经发送，不等于已经落地。先核现存入口。需要 JoinProject 或新建 Project 时，必须先有用户当轮明确允许，工具权限不能绕过。拒绝或找不到时写「不存在，或当前账号没有该团队权限」，不判定是哪一种，并写未加入、未发送。这不是已确认缺失，不重建。不换 id 试探。只有实际确认之后，才写加入、发送或设置成功。未经核验通过的旧协调器 id 不写成可用，也不写死进本仓库。当前账号 Projects 列表没有记录，不能单独当成缺失。

补当前账号自己的映射，以及按现有规则应有的工作台，不需要每条再等一次确认。验收、读回和正本冲突怎么挂起，见 `grokbot/BACKUP.md`「恢复与同步检查清单」。本文件不另抄清单，也不改认工作台正本在表还是在 `grokbot/workbench-map.md`。

花名册或用户标明暂停的项目只核离线映射。不唤醒、不派工、不测试、不建工作台。含 nova，以及已停的 M3（含支付）。

## 归属 Project

常驻工作台挂在花名册写明的 Cursor Project 下。映射表有「归属 Project」列。

- T8T 业务常驻工作台挂 T8T Project。
- 总控和通用问题挂「通用」Project。工作台映射与协作约定也放这里。
- 独立项目「工作台映射与约定」停用，不再使用。本文件不归档它。
- 测试专用 Project 保留，给测试框架、账号约定等专用事项，不并进通用。
- GO 尚无 Project。不预建工作台，不新建 GO Project。要建时再开 GO 项目并补常驻。

在用号的常驻工作台按花名册预建到对应 Project。需求分析仍是一条需求一条对话，不预建。日报、走查、周报只出报告，不建工作台。壳号和暂停号不建。暂停号不派活、不叫醒。

## 两条通道

工作台给思考、方案、代码草稿。默认模型是 Grok 4.7。

映射里有两种行：

- 常驻：一个在用项目号一条。需求标识留空。同类活续聊。这是角色主对话，不是 Project 协调器。
- 需求分析：一条需求一条对话，走该项目需求分析机器人的工作台。需求标识必填。不把多条需求续进同一条对话。同时处于「在用」的需求分析对话最多 5 条。这是需求子对话，不是 Project 协调器。

在用号的常驻工作台按花名册预建到对应 Project，状态写「在用」。不改成第一次有活才建常驻对话。需求分析不预建：没有独立需求，不建需求分析对话，不占常驻行。日报、走查、周报只出报告，不建工作台。壳号和暂停号不建。GO 尚无 Project，不预建工作台，不新建 GO Project。新开账号先写入账号对照，再新建`工作台-<账号名>`和`派单记录-<账号名>`。不同账号不要写进同一页。

升级走常驻 Ask、Plan、Debug、Multitask，再加上 `tools/ask_cursor.py`。一事一案，一个 Agent，一个 PR。这四个席位不是映射里的常驻行，不按机器人再复制。

分流：

- 思考、方案、代码草稿走该机器人自己的工作台对话。不跑 `ask_cursor.py prepare`。不占升级每日额度。
- 只有要改共享框架并开 PR 时，才走升级技能的 prepare / fix。
- 工作台不替代常驻 Ask、Plan、Debug、Multitask。
- 工作台不替代升级。

## 映射状态

状态只用这四个字：在用、空、停用、暂停。

在用号的常驻工作台按花名册预建到对应 Project，建完状态写「在用」，并填写「归属 Project」。没有对应 Project 的不预建。GO 尚无 Project，不预建，不新建 GO Project。

需求分析不预建。一条需求一条对话，有独立需求再开。

日报、走查、周报只出报告，不建工作台。对话列保持空。状态保持「空」，或在替换原因注明不建。壳号不建。

暂停号不建、不派活、不叫醒。含 nova，以及已停的 M3（含支付）。已有行状态写「暂停」，不删行。

## 何时新开

同一账号、同一机器人、同一项目的常驻对话必须续聊。只有三种情况可在原行新开对话：

1. 对话打不开、过期，或无法继续。
2. 已串项目或串了别的需求，或同一问连续两次答非所问。
3. 新启用的非暂停号，花名册要求有常驻工作台，而该行还没有对话。按花名册预建到对应 Project。日报、走查、周报、壳号、暂停号不建。需求分析不在此列。

在原行新开前，总控把旧 URL 写入「上一条 URL」，旧状态改停用，再把新地址写回原行。没有旧地址时，「上一条 URL」留空。

另一条需求是新的需求分析行，不占用旧需求那一行。

关闭需求分析对话要四项都有：需求标识；用例库标题和读回；知识库标题和读回，或写「无新增」；待确认已标明或写「无」。当天读回一致就关。分析中、没写回、读回不一致，不关。过期对话要迁移，不当成已回收。

## 简报必填

每笔简报都要有这些项：

- 账号（对应哪一页）
- 项目
- 任务一句
- 依据。没有依据就写「无依据，停」，并且不发。
- 禁做
- 已完成与证据位置
- 交付物和交齐标准
- 模型：Grok 4.7
- 续聊：是
- 盯守方
- 长任务：是或否

禁做固定为：不点页面，不跑业务测试，不写测试结论，不写凭证，不开 PR，不合并 PR。后两格的用法见下面「长任务沟通与盯检」。不另写一套简报。

## 拿回之后

机器人自己核。Cursor 说通过不算通过。不把草稿当测过。

给用户的回答要精简。先说结论。转述 Cursor 结果同样要短。汇报不含凭证。不合并 PR。

点页面、跑脚本、取证、写测试报告，仍由机器人自己做。

### 长任务沟通与盯检

本小节只补盯谁、何时开口。派活仍走「派工与接单」：有主管的项目由主管拆任务和派工，总控只转达。验收仍只有已接单、已收到成果、验收完成。同一任务已有负责人且已接单，不改派、不重复派。进度汇总仍只列名称、状态、有没有 PR，不读对话内容。

#### 什么算长任务

派单当时就能判断。满足任一条，就是长任务：

1. 要拆给多于一个子线程，或要等几路结果汇合后，才能给用户一句结论。
2. 完成前没有需要用户立刻拍板的新事实。中间状态不会改变用户的决定。
3. 这单已经在某个盯守方手里，还没交齐。

一个角色在原对话里一轮就能答完，并且用户正在等这一句：这不是长任务。直接在原对话答完。不走协调器，不另开跑次。这与现有「一问一答的活不走协调者」是同一句。

#### 活交给谁

一次只交给一个对话，并在简报里写明盯守方。

- 不拆活：交给接单角色已有的常驻对话，或那条需求子对话。盯守方就是该对话。协调器不接这单，不汇总，不因收尾再跑一轮。
- 要拆活，或要几路汇合：只交给该 Project 的协调器。盯守方就是该协调器。总控不对子线程发话。
- 跨项目方案、协作约定、工作台映射：留在总控（King）工作台。盯守方就是本工作台。不另交协调器做「已记录」确认。
- 已经有盯守方：续原对话。不再交给第二个对话。

业务执行（点页面、跑脚本、取证、写测试结论）仍由对应机器人做，不改成 Cursor 盯守方去做。

#### 同一条任务只有一个盯守方

盯守方是总控发话的那一个对话，也是唯一会在跑完时叫醒总控的对话。

- 派给协调器时，总控不订子线程，不把子线程收尾当成给总控的叫醒。
- 派给常驻或需求对话时，协调器不拆、不转述、不平行再开一份。
- 总控不同时盯协调器和子线程。
- 第二个 Grok 机器人、另一条 Cursor 对话、另一个 Project，看到同一任务一句，就停在原处，不接、不盯、不追问。

#### 协调器何时回总控

只在下面三种情况给总控发一条。每种只发一次。附执行方聊天入口。

1. 交齐：一句结论，交付物在哪，还有没有要人点头的一项。没有就写「无」。
2. 阻塞：缺什么、卡在谁、不决定会怎样。原负责人不变。
3. 范围要改：原任务一句已经盖不住。停在原地，等点头后再做。

#### 协调器何时沉默

下面这些情况，协调器结束本轮，不发消息，不新开跑次：

- 子线程回报已记录、待命、无新决定。
- 只是已收到、已开始、还在跑，或任何进度。
- 整单还没齐，并且不是阻塞，也不是范围要改。
- 想告诉总控「不必再告诉用户」。这句话不要发。沉默代替它。

子线程只回自己的盯守方一条结果。不给总控发，不给别的协调器发，不在正文里要求再通知用户，也不要求不要通知用户。

#### 总控何时告诉用户

总控只转述盯守方的三种回音，每种说一次。先说结论，再附执行方聊天入口。汇报不含凭证。

被「已记录、待命、不必告诉用户」叫醒时，不回复。回复会再开一轮。同一事实不说第二次。

#### 避免多号同时接同一份活

发简报前先查三处。任一处已经在途，就只续原盯守方：

1. 派工与接单：同一任务已有负责人且已接单。
2. 当前账号的工作台页和派单记录：同一任务一句已有在用对话。
3. 另一个 Grok 号或另一个 Project 已经在做这单。

简报在原有八项之外加两格，不另写一套简报：盯守方；长任务（是或否）。

不把同一份简报贴进两条对话。不广播。不新开对话。不新建 Project。不叫醒花名册标明暂停的号，含 M3、支付、nova。小程序不进本约定。

#### 长任务进行中不追问进度

长任务从发出到三种回音之一出现之前，总控、协调器、Grok 机器人、子线程都不发「到哪了」「收到了吗」「请再确认已记录」。

用户当轮明确问进度时，只由盯守方答一条：名称、状态、有没有要人点头的项。不读对话内容，不新开对话，不叫醒其他号。没有用户当轮提问，就不做这次汇总。

「派工与接单」里到点查未完项，仍只在该技能约定的时点做一次，不改成轮询，也不因此再叫醒第二条 Cursor 对话。

派单记录写在当前账号的`派单记录-<当前账号>`。列是：日期、项目、机器人、续聊或新建、任务一句、对话 URL、核验结果。

工作台不占升级每日额度。
