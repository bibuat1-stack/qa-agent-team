# 复现缺陷报告（机器人优化版）

面向 UI / 渲染 / 交互类缺陷。纯后端、构建、依赖问题除非用户明确要求视觉复现，否则不用本技能。

## 与现有技能关系

- 有票要拆复现步骤：可先 `repro-from-ticket` / `repro-from-screenshot`
- 网页优先 Playwright MCP / [playwright-cli](sand-workflow:playwright-cli) / [agent-browser](sand-workflow:agent-browser)
- 桌面/canvas 才 computerUse
- 证据脱敏见 [evidence-hygiene](sand-workflow:evidence-hygiene)
- 硬缺陷系统诊断见 [diagnosing-bugs](sand-workflow:diagnosing-bugs)

## 主流程

1. 抽出：现象、期望、步骤、环境约束、附件线索
2. 判断是否适用本技能。缺凭证或私有态无法在授权环境拿到时，直接报阻塞，不猜
3. 路径清晰：一次探路复现。多假设：分次变体，不并行抢同一测号
4. 步骤不全：用本项目知识库与代码线索提出有依据的假设，标明未证实
5. 全部变体跑完再汇总。区分确认 / 部分确认 / 未复现 / 阻塞 / 未测假设

## 环境

1. 尽量对上报告里的版本/渠道。对不上就写清楚请求版本、实装版本、来源与为何退而求其次
2. 不静默换成最新包冒充原环境
3. 测号与登录走 Vault / sign-in。禁止生产真号

## 证据

1. 默认录短屏。静态渲染才以截图为主
2. 截图有序命名：`01-初始.png`、`02-点击前.png`
3. 目录内留简短清单：文件名、时间、可见状态、刚做的动作、是否已现缺陷
4. 禁止凭证、Authorization、私人账号细节进录屏/截图/日志外发

## 复现动作

1. 先记环境：OS、浏览器、站点、版本
2. 先按报告步骤原样走
3. 不现再测已写明的假设，最多两次有依据变体
4. 崩溃/卡住：截图 + 脱敏日志
5. 现了就停变量，补足可行动证据

## 汇总模板

```text
缺陷摘要：编号、现象、期望
复现状态：确认 | 部分确认 | 未复现 | 阻塞
测了什么：变体、步骤、环境
证据：路径 + 一眼说明
发现：与报告差异、可能状态（标未证实）
下一步：一条具体动作或要问用户的一点
```

不自动改代码、不自动对外发帖。故障仍按协作技能报总控。
