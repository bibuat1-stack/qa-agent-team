# 复现缺陷报告（机器人优化版）

面向 UI / 渲染 / 交互类缺陷。纯后端、构建、依赖问题除非用户明确要求视觉复现，否则不用本技能。

## 先写最小可证步骤

报告不全、偶发、或环境相关时，先证明最小可观察失败，再谈诊断或修复。建简报期间不改产品代码。

1. **记现象**：确切错误或错误输出、时间、路由或命令、已知最小输入。日志脱敏。二手描述标未证实。
2. **记环境**：能查到的才写。不猜凭证与生产配置。
3. **拆期望与实际**：两句可观察陈述，不把猜因写进去。
4. **缩小**：按报告路径走，再逐项去掉无关数据与步骤。保留仍失败的最小步骤。失败消失则恢复最后去掉的条件并记下。
5. **可重复**：安全时至少跑两次。偶发则写频率与窗口，不谎称必现。
6. **停在修复前**：简报是这一步的交付物，不边复现边改产品代码。

简报用下面这几栏：目标与提交；环境；期望；实际；最小复现步骤或命令；重复（必现 / 约 N/M）；证据路径；未证实；下一步（一条诊断动作）。

## 与现有技能关系

- 探路见 [box-ui-speed](sand-workflow:box-ui-speed)，默认 playwright-cli。桌面/canvas 才用 computerUse。不把三种工具写成并列可选。
- 证据脱敏见 [evidence-hygiene](sand-workflow:evidence-hygiene)
- 硬缺陷系统诊断见 [diagnosing-bugs](sand-workflow:diagnosing-bugs)。诊断前先完成上面的最小可证步骤。

## 主流程

1. 抽出：现象、期望、步骤、环境约束、附件线索
2. 判断是否适用本技能。缺凭证或私有态无法在授权环境拿到时，直接报阻塞，不猜
3. 路径清晰：一次探路复现。多假设：分次变体，不并行抢同一测号
4. 步骤不全：用本项目知识库与代码线索提出有依据的假设，标明未证实
5. 全部变体跑完再汇总。区分确认 / 部分确认 / 未复现 / 阻塞 / 未测假设

## 环境

1. 尽量对上报告里的版本/渠道。对不上就写清楚请求版本、实装版本、来源与为何退而求其次
2. 不静默换成最新包冒充原环境
3. 测号与登录走 Vault / sign-in。禁止生产真号

## 证据

1. 默认录短屏。静态渲染才以截图为主
2. 截图有序命名：`01-初始.png`、`02-点击前.png`
3. 目录内留简短清单：文件名、时间、可见状态、刚做的动作、是否已现缺陷
4. 禁止凭证、Authorization、私人账号细节进录屏/截图/日志外发

## 复现动作

1. 先记环境：OS、浏览器、站点、版本
2. 先按报告步骤原样走
3. 不现再测已写明的假设，最多两次有依据变体
4. 崩溃/卡住：截图 + 脱敏日志
5. 现了就停变量，补足可行动证据

## 汇总模板

```text
缺陷摘要：编号、现象、期望
复现状态：确认 | 部分确认 | 未复现 | 阻塞
测了什么：变体、步骤、环境
证据：路径 + 一眼说明
发现：与报告差异、可能状态（标未证实）
下一步：一条具体动作或要问用户的一点
```

不自动改代码、不自动对外发帖。故障仍按协作技能报总控。
