  在 Notion 给一个项目建测试知识库：一页系统地图加 5
  个互相关联的数据库（资料索引、知识点、测试用例、缺陷、测试日志），知识点用关联连成网。用户说「建库」或要给新项目建知识库时使用。

【版本】v2，2026-11-10。原文视为 v1。本次改知识点和测试用例「编号」说明为手工文本编号。

【何时用】给新项目建知识库。需要项目名、模块列表、父页面；缺哪个就问。

【顺序】关联等目标库建好再加，自关联等知识点库建好再加，公式等关联都加好再加。
1. 父页面下建首页「{项目名} · 测试知识库」，正文：先读系统地图，再按模块查知识点；写知识点必须连关联；账号密码不进库。
2. 首页下建「系统地图」，四节：模块（表：模块｜负责什么｜和谁耦合，不知道写待补）、核心业务对象（对象｜谁改变它｜谁依赖它）、耦合热点、待确认。
3. 首页下依次建 5 个库：资料索引、知识点、测试用例、缺陷、测试日志。
4. 加关联，最后加公式和视图。

【数据库和属性】每个库「模块」都是多选，选项用{模块列表}加「通用」。
1. 资料索引：名称（标题）、类型（需求文档/接口文档/用例文档/测试报告/会议纪要/群公告）、模块、链接（网址）、版本或日期（文本）。
2. 知识点：标题、编号（文本，手工填写，按本库已有格式递增，如 K-12、KP-4、M3K-3；写前先查当前最大编号，不重号）、类型（功能/业务对象/规则/配置/接口事件/坑点/决策）、模块、要点（文本）、状态（已确认/待确认/已过期）、来源（需求文档/产品确认/开发确认/实测/群聊）、最后核实（日期）、更新时间（最后编辑时间）。双向自关联三组：上级↔下级、改变↔被改变、依赖↔被依赖。单向自关联：替代条目。来源资料：双向关联到资料索引，那边叫「知识点」。
3. 测试用例：标题、编号（手工文本编号，按本库已有格式递增，写前查当前最大编号，不重号）、模块、场景（正向/异常/边界/兼容/联动）、优先级（P0-P3）、最近结果（未测/通过/不通过/阻塞/忽略）、最近执行（日期）、设备环境（文本）。覆盖：双向关联到知识点，那边叫「覆盖用例」。前置、步骤、预期写正文。
4. 缺陷：标题、单号（文本）、模块、严重程度（致命/严重/一般/轻微）、状态（新建/处理中/待复验/复验通过/复验不通过/已关闭）、耦合类型（共享数据/共享配置/调用链/规则冲突/时序并发/无）、设备环境、提交日期。涉及：双向关联到知识点，那边叫「相关缺陷」。关联用例：双向关联到测试用例，那边叫「关联缺陷」。复现步骤和复验记录写正文。
5. 测试日志：标题（YYYY-MM-DD 周X）、日期、涉及知识点（关联）、新增缺陷（关联）。正文五节：做了什么、发现、知识变更、没做完、下一步。

【公式】照抄
- 知识点「关联一览」（文本）：
[if(prop("上级").length() > 0, "上级：" + prop("上级").map(current.prop("标题")).join("、"), ""), if(prop("改变").length() > 0, "改变：" + prop("改变").map(current.prop("标题")).join("、"), ""), if(prop("被改变").length() > 0, "被改变：" + prop("被改变").map(current.prop("标题")).join("、"), ""), if(prop("依赖").length() > 0, "依赖：" + prop("依赖").map(current.prop("标题")).join("、"), ""), if(prop("被依赖").length() > 0, "被依赖：" + prop("被依赖").map(current.prop("标题")).join("、"), "")].filter(current != "").join("｜")
- 知识点「扇入」（数字）：
prop("被改变").length() + prop("被依赖").length()
- 知识点「风险标记」（文本）：
[if(prop("被改变").length() >= 2, "多方改写", ""), if(prop("被改变").length() + prop("被依赖").length() >= 5, "高扇入", ""), if((prop("类型") == "功能" || prop("类型") == "规则") && prop("状态") == "已确认" && prop("覆盖用例").length() == 0, "无用例", ""), if(prop("相关缺陷").length() > 0, "有缺陷", ""), if(prop("上级").length() + prop("下级").length() + prop("改变").length() + prop("被改变").length() + prop("依赖").length() + prop("被依赖").length() == 0, "孤立", ""), if(prop("状态") == "待确认", "待确认", "")].filter(current != "").join("、")
- 缺陷「跨模块」（文本）：
if(prop("涉及").map(current.prop("模块")).flat().unique().length() >= 2, "跨模块", "")

【视图】建得了就建
- 知识点：耦合热点（风险标记不为空，按扇入降序）、待确认、最近更新。
- 缺陷：未关闭（状态不是已关闭、复验通过）、跨模块。

【校验】
- 逐个打开数据库，确认属性、关联两边名字、公式都在。
- 用一个真实功能和它改动的业务对象各建一条，连「改变」，看「关联一览」「风险标记」是否算出。没有真实功能就先问用户要一个。
- 公式报错的，把原报错和改后写法都告诉用户。

【返回】首页、系统地图、5 个数据库的链接，以及没建成的部分和原因。

【需要确认】父页面位置；已有同名页面时复用还是新建。
