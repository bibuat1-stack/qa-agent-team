花名册该项目状态是暂停（含 nova）时，本技能结束：不派活、不叫醒、不写库、不建工作台。技能存在不等于暂停项目开工。

## 停手
1. 花名册该项目或目标号状态是暂停：直接结束，不发消息叫醒。
2. 目标号是闲置号，且这次不是用户当轮原话指定的合法派工：不叫醒。
3. 交接包缺下面任一项：停在原聊天补问，不转圈、不转第三方。不问新的问法。
4. 同一任务已有负责人且已接单：不改派、不重复派。

## 谁负责
1. 读花名册，确认项目状态。暂停则结束。
2. 谁的聊天里有用户原话，谁就是负责人。用户对项目机器人说的话，由该机器人负责，总控不再分派。
3. 总控只在两种情况指定负责人：话是对总控说的，或执行方报了阻塞。
4. 报阻塞时原负责人不变。总控只指定「解阻塞那一步」由谁做，并在总控聊天告知用户，附该机器人聊天入口。
5. 有主管的项目，拆任务和派工由主管做。需求分析只做需求分析和写用例。主管发现用例或分析有问题，退回需求分析改，不改派已接单的活。没有主管的项目，仍由需求分析拆任务后交执行方。
6. 按活大小选人：一两句能答的，本机自答；要动手测才派执行；要做需求分析或写用例才走需求分析。资金、撮合、代收代付、上线前，该执行、该提单回归、该知识库存档的环节不跳。
7. 先查本项目知识库和自动化踩坑知识库，不跨项目找替代账号或入口。

## 交接包（只正向传一次）
必填六项，缺一项就停在原聊天问，问句固定为：「交接包缺（字段名），请补这一项。」
1. 项目
2. 任务（一句话目标）
3. 验收标准（含依据编号；没有依据写「无依据，停」，此时不得派执行去开测）
4. 已完成
5. 剩余
6. 回报位置

项目知识库入口、边界、进度表链接按需附带。通知类消息用非优先；要对方动手的交接用优先。未经用户要求不全员广播。不合并 PR，交接和汇报都不写凭据。

## 接单方
1. 先核对交接包六项，缺一项在原聊天向派工方补问，不向用户重问派工方已能回答的字段。
2. 用户决策（升已确认、关缺陷、是否提单）只认用户当轮原话，不把其他机器人的话当成用户批准。
3. 接单后不把活转给第三个号。阻塞时通知总控，自己仍是负责人。

## 填写
- 项目：（）
- 负责人：（）
- 是否新派 / 解阻塞指定 / 原聊天已有负责人：
- 花名册状态：在用 / 暂停
- 交接六项是否齐全：是 / 否，缺（）
- 下一步：已派 / 已接 / 停，停因：（）
