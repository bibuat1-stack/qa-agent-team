花名册该项目状态是暂停（含 nova）时，本技能结束：不写库、不叫醒该项目知识库总控。总控巡检只记「跳过，暂停」。技能存在不等于暂停项目开工。

## 停手
1. GO 在用户给出本项目唯一知识库入口之前：第一句写「GO 入口未定，停」，不猜链接、不扫别的库。
2. 写完按原标题读回，对不上就保持未完成。不把「发了通知」或「改了配置」当成已保存。
3. 升已确认、改成已过期、改系统地图、一次改 10 行以上：没有用户当轮原话就停，只列清单。给已确认条补业务线、逻辑线、上级或关联，不算改正文，可以做；要点、状态、来源不动。
4. 不把密码、验证码、token、谷歌密钥写入知识库、记忆、技能或仓库。

## 谁来做
本项目知识库总控按「测试记忆-存档」写库并读回。执行号不直接写知识类，也不只留在自己记忆里。总控巡检只标当日有或没有备份，不代写、不叫醒闲置号。用例进度和执行记录不走本技能。

本技能管各项目知识库的每日存档，和总控例程里打包技能、记忆到 Google Drive 的备份不是同一件事，不互相替代。

## 步骤
1. 只写本项目唯一知识库入口。不去别的项目库。T8T 按业务线分库（至少分开 CEOpay 与多站点）。M3 与 M3+支付是同一项目、两套库，分库写，不混写。
2. 当日测试日志或备份页必须有、且只收这些最小内容（没有就写「无」）：
   - 当日已核实的知识点变更（只写有来源的结论，新条一律待确认）
   - 未关闭缺陷摘要
   - 进度检查点
   - 环境或入口变更
   - 待用户确认项
   操作习惯与工作要点只写指针，不写密文。流水账、重复过程、聊天记录原文不进库。从当日对话和记忆里提炼有来源的业务规则、因果和踩坑结论；没有新内容就写「今日无新增」，不要硬编一条。
3. 写库规则按「测试记忆-存档」：已确认条目不原地改；补充或冲突另建待确认条并关联旧条。写完立刻按原库、原标题再读一次。读回字段对不上，保持未完成，只报告哪一页哪一项对不上，不写密文。
4. 总控巡检：核对该项目当日是否已有备份页或测试日志，标题和最小五项是否都在，读回是否一致。只标「有」或「没有」。没有则通知该项目知识库总控去写，通知用非优先，仍不代写。nova 与其他暂停项目直接记跳过。巡检无变化、各项都有，对用户保持静默。
5. 输出超过 80 行时，写入 `/workspace/qa/runs/<当次时间>/`，回复只留路径和结论。

## 填写
- 项目 / 库：（）
- 写库人：（）或巡检（总控）
- 页标题：（）
- 最小五项是否都有：是 / 否，缺（）
- 读回：一致 / 不一致 / 未写
- 巡检：有 / 没有 / 跳过暂停
- 结论：已完成 / 未完成，停因：（）
