  个互相关联的数据库（资料索引、知识点、测试用例、缺陷、测试日志、执行记录），知识点用关联连成网。用户说「建库」、要给新项目建知识库，或要给已有库补测试日志类型和按类型、日期查找的视图时使用。不拆库，不为重粉库另建测试日志库。

【版本】v5，2026-11-21。测试用例属性增加「撰写人」，与「执行人」分开。新建或改未放行正文时必填：机器人写就写该机器人名，Cursor 工作台写就写「Cursor」。不要只为补这个字段去改已放行正文。已有用例不批量回填，除非用户再说。v4，2026-11-16。v2（2026-11-10）改知识点和测试用例「编号」为手工文本编号。v3（2026-11-11）改测试用例属性与执行记录库、同步视图、首页写库说明。v4 只补已确认的查找约定：测试日志增加单选「类型」，新写先选类型；测试日志默认「按类型」，并加「按日期」「日历」；资料索引默认改「按类型」，并加「按模块」，不改字段选项；执行记录加「按结果」，已有同步视图保留；测试用例三份同步视图保留，不重命名 Default；首页原有目录保留，下面补一段「怎么找」。不拆库，不改日志正文五节，不为重粉库另建测试日志库。已有库不要重建，只补缺的属性和视图。

【何时用】给新项目建知识库。需要项目名、模块列表、父页面；缺哪个就问。已有库只补缺的属性和视图，不重建、不拆库。

【顺序】关联等目标库建好再加，自关联等知识点库建好再加，公式等关联都加好再加。
1. 父页面下建首页「{项目名} · 测试知识库」，正文：先读系统地图，再按模块查知识点；写知识点必须连关联；账号密码不进库。知识点只由知识库总控写。用例进度和执行记录各角色直接写自己的属性。首页原有目录保留，不替换。目录下面补一段短的「怎么找」：测试日志默认看「按类型」，按天看用「按日期」或「日历」；资料索引默认看「按类型」，按模块看用「按模块」；测试用例仍用同步-日常、同步-测试中、同步-已归档；执行记录看结果用「按结果」。
2. 首页下建「系统地图」，四节：模块（表：模块｜负责什么｜和谁耦合，不知道写待补）、核心业务对象（对象｜谁改变它｜谁依赖它）、耦合热点、待确认。
3. 首页下依次建 6 个库：资料索引、知识点、测试用例、缺陷、测试日志、执行记录。
4. 加关联，最后加公式和视图。

【数据库和属性】每个库「模块」都是多选，选项用{模块列表}加「通用」。
1. 资料索引：名称（标题）、类型（需求文档/接口文档/用例文档/测试报告/会议纪要/群公告）、模块、链接（网址）、版本或日期（文本）。
2. 知识点：标题、编号（文本，手工填写，按本库已有格式递增，如 K-12、KP-4、M3K-3；写前先查当前最大编号，不重号）、类型（功能/业务对象/规则/配置/接口事件/坑点/决策）、模块、要点（文本）、状态（已确认/待确认/已过期）、来源（需求文档/产品确认/开发确认/实测/群聊）、最后核实（日期）、更新时间（最后编辑时间）。双向自关联三组：上级↔下级、改变↔被改变、依赖↔被依赖。单向自关联：替代条目。来源资料：双向关联到资料索引，那边叫「知识点」。
3. 测试用例：正式编号、临时编号、需求编号、模块、标题、优先级（P0 到 P2）、风险（高、中、低）、用例类型（日常、需求）、国家/站点、知识库、步骤要点、预期、依据编号、依据更新时间、覆盖（双向关联到知识点，那边叫「覆盖用例」）、评审状态（未评审、可执行、待核实、阻塞、已放行、建议删除、不计入）、签字（已签、拒签）、最近结果（未测、进行中、失败、阻塞、已跑待评审、已跑待确认、通过）、实际结果、证据路径、撰写人、执行人、最近执行、执行次数、待确认问题、产品答复、来源需求、纳入回归、备注、归档日期、关联缺陷（双向关联到缺陷，那边叫「关联用例」）、执行记录（双向关联到执行记录库，那边叫「用例」）。
4. 缺陷：标题、单号（文本）、模块、严重程度（致命/严重/一般/轻微）、状态（新建/处理中/待复验/复验通过/复验不通过/已关闭）、耦合类型（共享数据/共享配置/调用链/规则冲突/时序并发/无）、设备环境、提交日期。涉及：双向关联到知识点，那边叫「相关缺陷」。关联用例：双向关联到测试用例，那边叫「关联缺陷」。复现步骤和复验记录写正文。
5. 测试日志：标题（YYYY-MM-DD 周X）、日期、类型（单选：每日存档、日报周报、需求测试、缺陷跟进、专项压测、造数批次、其他）、涉及知识点（关联）、新增缺陷（关联）。新写一条必须先选类型。正文五节不改：做了什么、发现、知识变更、没做完、下一步。不拆库，不为重粉库或别的需求另建测试日志库。
6. 执行记录：记录键（标题，约定「正式编号|执行时间」）、用例（关联用例库）、正式编号、临时编号、需求编号、结果（词表同最近结果：未测、进行中、失败、阻塞、已跑待评审、已跑待确认、通过）、实际结果、证据路径、执行人、执行时间、轮次、环境、备注。

旧选项「不通过」「忽略」「P3」等，库里没有页在用了再删。先删会把已有的值清空。已有库不要重建，只补缺的属性和视图，改成与现状一致。

【公式】照抄
- 知识点「关联一览」（文本）：
[if(prop("上级").length() > 0, "上级：" + prop("上级").map(current.prop("标题")).join("、"), ""), if(prop("改变").length() > 0, "改变：" + prop("改变").map(current.prop("标题")).join("、"), ""), if(prop("被改变").length() > 0, "被改变：" + prop("被改变").map(current.prop("标题")).join("、"), ""), if(prop("依赖").length() > 0, "依赖：" + prop("依赖").map(current.prop("标题")).join("、"), ""), if(prop("被依赖").length() > 0, "被依赖：" + prop("被依赖").map(current.prop("标题")).join("、"), "")].filter(current != "").join("｜")
- 知识点「扇入」（数字）：
prop("被改变").length() + prop("被依赖").length()
- 知识点「风险标记」（文本）：
[if(prop("被改变").length() >= 2, "多方改写", ""), if(prop("被改变").length() + prop("被依赖").length() >= 5, "高扇入", ""), if((prop("类型") == "功能" || prop("类型") == "规则") && prop("状态") == "已确认" && prop("覆盖用例").length() == 0, "无用例", ""), if(prop("相关缺陷").length() > 0, "有缺陷", ""), if(prop("上级").length() + prop("下级").length() + prop("改变").length() + prop("被改变").length() + prop("依赖").length() + prop("被依赖").length() == 0, "孤立", ""), if(prop("状态") == "待确认", "待确认", "")].filter(current != "").join("、")
- 缺陷「跨模块」（文本）：
if(prop("涉及").map(current.prop("模块")).flat().unique().length() >= 2, "跨模块", "")

【视图】建得了就建。已有库只补缺的，不重建。
- 知识点：耦合热点（风险标记不为空，按扇入降序）、待确认、最近更新。
- 缺陷：未关闭（状态不是已关闭、复验通过）、跨模块。
- 资料索引：默认视图改成「按类型」（GROUP BY 类型，SHOW EMPTY）。另加「按模块」（GROUP BY 模块，SHOW EMPTY）。类型、模块的选项不改。
- 测试用例：同步-日常（用例类型是日常）、同步-测试中（用例类型是需求，归档日期为空）、同步-已归档（用例类型是需求，归档日期不为空）。这三份保留不改，不重命名 Default。
- 测试日志：默认视图改名或配成「按类型」（GROUP BY 类型，SHOW EMPTY，组内按日期倒序）。另加「按日期」（按日期倒序）、「日历」（CALENDAR BY 日期）。
- 执行记录：同步-执行记录（按执行时间升序）保留。另加「按结果」（GROUP BY 结果，SHOW EMPTY，按执行时间倒序）。

【校验】
- 逐个打开数据库，确认属性、关联两边名字、公式都在。
- 用一个真实功能和它改动的业务对象各建一条，连「改变」，看「关联一览」「风险标记」是否算出。没有真实功能就先问用户要一个。
- 公式报错的，把原报错和改后写法都告诉用户。

【返回】首页、系统地图、6 个数据库的链接，以及没建成的部分和原因。

【需要确认】父页面位置；已有同名页面时复用还是新建。
