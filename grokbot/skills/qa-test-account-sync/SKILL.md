花名册该项目状态是暂停时，本技能只允许读写账号正本，不派活、不叫醒该项目机器人、不写业务知识库、不建工作台。本技能存在不等于暂停项目开工。

## 停手
出现下面任一情况就停。停因里可以写测试账密。不写谷歌密钥、验证码、token 的值：
1. 用户要查或改的项目、系统或账号别名说不清。问句固定为：「要查或改的是哪个项目、哪个系统、哪个账号？」
2. 用户要看测试账密时，直接给出账号和密码。不改成只给页名、表名或指针。谷歌密钥、验证码、token 仍不贴进聊天、通知、记忆或仓库。
3. 用户没有当轮原话要求时，不改旧表「各项目测试账号与凭证」。该旧表不再作为官方查找处。
4. 正表和已写入的 Notion、本地文件读回不一致，保持未完成，不把其中一处当已同步。
5. 本地和完整库都没有，环境又不允许创建，也还没有可写回的账密：停，不得编造密码，不叫用户去填保险库。
6. 不把完整库里的全部账号往「测试账号-给人看」里堆。
7. 密钥类只记是否存在。禁止复制、删除、重置、改值。不要用「有」或「没有」去覆盖已填的密钥格。

## 正本（只写名字和路径，不写网页链接）
- 本地，机器人云电脑：`/workspace/qa/secrets/qa-test-accounts.md`
- 本地，那台 Windows：`C:\Users\青鸟\Documents\qa-test-accounts.md`
- 谷歌正表：表名「测试账号-完整库」，按项目分工作表，放全部账号
- Notion：页名「测试账号」，同步写入处，不是查找第一来源
当前机器没有上述本地文件时，直接查「测试账号-完整库」。云端表的网页地址不写进本技能。

给人看的表名是「测试账号-给人看」：有目录和按项目分表，不放全部账号；按域名最多 3 条，用户给的主号优先；目录和每个项目表都要链到正表；账号来源写清。它不是查找第一来源。

查找顺序：先本地，本地没有再查「测试账号-完整库」。机器人和 Cursor 都按这个顺序。Notion 是同步写入处，不是查找第一来源。有账号或可以自己创建时，不弹安全账号、保险库或安全表单。会推到 GitHub 的文件可以写测试账密明文。密钥类的值仍不写进这些文件。

本机和 Notion 用同样的简单表头：环境、系统、域名、账号、密码、谷歌密钥、保险库登录名、用途、更新日期。两本谷歌表保持现有可视化列，不改表头，除非用户当轮要求优化。环境名按本项目知识库已确认叫法写；域名里的字不是环境名。保险库登录名只是已有列名。查找和登录不读它，也不弹保险库。

## 查找
1. 先找本地。当前机器是机器人云电脑，就读 `/workspace/qa/secrets/qa-test-accounts.md`。当前机器是那台 Windows，就读 `C:\Users\青鸟\Documents\qa-test-accounts.md`。按项目、系统、环境、账号别名定位行。当前机器上没有这份文件，就做第 2 步。
2. 本地没有该行，再打开「测试账号-完整库」对应项目工作表定位。不要把旧表「各项目测试账号与凭证」当官方查找处。不要只在「测试账号-给人看」里查缺。
3. 找到且该行账号、密码齐全：直接用于登录。不弹安全账号、保险库或安全表单。测试账密可以写入聊天、记忆、报告和仓库。密钥类只记是否存在，不写值。
4. 本地和完整库都没有该行，或有行但账号或密码不全：
   - 环境允许创建：自己创建测试号，然后立刻走「增加或更新」写回并读回。不编造密码。
   - 环境不允许创建，也还没有可写回的账密：停，写：「本地和完整库都没有这个账号，停。」不跨项目借用，不叫用户去填保险库。
   - 用户当轮已经给了账密，或本轮已经用来登录：立刻走「增加或更新」写回并读回，不等用户再说「同步」。

## 增加或更新（账号增加或测试密码更新）
1. 先读正表「测试账号-完整库」、Notion 页「测试账号」，以及自己碰得到的本地文件，做合并：任一处已有的非空账号和密码，没有用户当轮原话要求删除，就保留。不准用空值覆盖已有值。
2. 谷歌密钥以及其他密钥类：只记是否存在。禁止复制、删除、重置、改值。用户附了密钥图片也不把值写入聊天、文档、仓库或正表。已填的密钥格不要改。
3. 人给的账号：先写碰得到的本地文件，再写「测试账号-完整库」对应项目工作表，再写 Notion「测试账号」页，再按规则更新「测试账号-给人看」（每域名最多 3 条，用户给的主号优先，来源写清，并保留链到正表的链接）。
4. 机器人大批量生成的测试账号：默认只写碰得到的本地文件和「测试账号-完整库」，不写入「测试账号-给人看」。
5. 写谷歌表时按字面写入，不要让表格把 `+`、`^` 当成公式。
6. 写 Notion 时，测试账密按原文写入。密钥类不写值。
7. 碰不到机器人云电脑或 Windows 那份本地文件时，写明哪一份待补，不能假装本地也写过。
8. 写完立即按原路径、原页名、原表名再读一次。比较账号和密码前，先去掉 Notion 可能加上的转义（例如 `^` 写成 `\^`）。未转义的原文是比较基准。
9. 正表和已写入的 Notion、本地文件的账号、密码、用途一致，才算同步完成。不一致则保持未完成，只报告哪一处哪一列对不上（列名，不写值）。读回对不上时以重读原文为准。给人看的表只核应出现的行和条数规则，不因完整库多出的批量账号判失败。

## 填写

- 项目：（）
- 系统 / 环境 / 账号别名：（）
- 动作：查找 / 新增 / 更新
- 更新了哪些列：（只写列名）
- 是否批量生成：是 / 否
- 本地读回：一致 / 不一致 / 未写 / 待补
- 完整库读回：一致 / 不一致 / 未写
- Notion 读回：一致 / 不一致 / 未写
- 给人看：已按规则更新 / 未写入（批量） / 未写 / 规则不符
- 结论：正本已对齐 / 未完成，停因：（）
