花名册该项目状态是暂停（含 nova）时，本技能结束：不建工作台、不续聊、不写映射。技能存在不等于暂停项目开工。日报、走查、周报不建工作台。

## 停手
1. 简报缺下面任一项：停，不发。问句固定为：「简报缺（字段名），请补这一项。」依据没有时，依据栏写「无依据，停」，这份简报不发。
2. 本次要改共享框架并且要开 PR：本技能停笔，改走「Cursor专家升级」和 `ask_cursor`，同一问题只保留一个案例、一个 Agent、一个 PR。工作台里只留案例链接，不在工作台开 PR。
3. 同一账号里已有状态「在用」的对话时，不是下面「可以新开」的三种情况：必须续聊，不新开窗口。还没有行的新需求按步骤 3 新建一行，不把旧需求那一行改掉。不得续聊另一个账号的对话。

## 谁来做
本机器人写简报并贴进自己的工作台。总控先查映射正本、告诉续哪一条、写映射正本，不代写项目简报。思考、方案、改代码草稿交给 Cursor；点页面、跑脚本、取证、写测试结论仍由机器人自己做。

## 步骤
1. 先打开仓库映射正本 `grokbot/workbench-map.md` 里对应账号那一页。现在先打开「工作台-Faker」。对话地址和对话 id 写在这份正本里。不要去「工作台-sacks」续聊，那些稳定 id 已失效，不要当成当前号。谷歌表只是同步副本。谷歌硬盘只保存全量压缩包；日常先同步到 Git，再备份压缩包到硬盘。不写密码、token、密钥、测号、凭证表链接，也不把压缩包或记忆正文写进仓库。常驻活在「工作台-Faker」查本项目、本机器人、用途「常驻」那一行。需求分析是一条需求一条对话：在同一页查本项目、本机器人、用途「需求分析」、本需求标识那一行。GO电子是壳号，不建工作台。小程序不进本表。
2. 已有对话且状态是「在用」：必须续聊，把简报贴进该对话，并请总控把「上次续聊日期」改成当天。
3. 本账号这一页里对话列为空、状态是「空」：这是该常驻号或该需求的第一笔思考、方案或代码活，才新建一条对话。默认模型 Grok 4.7，上下文 256K，力度 High，打开 Fast。建在仓库 `qa-agent-team` 下，不要无仓库。建完由总控写入「工作台-Faker」：对话地址、对话 id、模型、状态「在用」、开设日期。Faker 常驻行已经登记，对话列保持空，直到真有这类活。不预建空的需求分析行。日报、走查、周报只出报告，不建对话。同时处于「在用」的需求分析对话最多 5 条。新开账号先在账号对照登记，再新建「工作台-账号名」和「派单记录-账号名」。不同账号不要写进同一页。
4. 只有这三种情况可以在原行新开，且须总控先把旧地址写入「上一条 URL」、旧状态改成「停用」，再把新地址写入原行：
   - 对话打不开、已过期或无法继续发送；
   - 上下文已经串项目或串了别的需求，或同一问连续两次答非所问；
   - 新启用一个非暂停号，并且它有第一笔思考或代码活。没有旧地址时，「上一条 URL」留空。
   换一天、换一条用例、想要空白窗口，都续聊。另一条需求另开一行，不改旧需求那一行。跨项目框架问题进常驻 Plan，不进任何一个项目工作台。关闭需求分析对话要四项都有：需求标识；用例库标题和读回；知识库标题和读回，或写「无新增」；待确认已标明或写「无」。当天读回一致就关。分析中、没写回、读回不一致，不关。过期对话要迁移，不当成已回收。
5. 简报必须写满这九项，缺一项不发：
   - 账号（对应哪一页）
   - 项目
   - 任务（一句）
   - 依据（知识点编号或文档位置；没有写「无依据，停」）
   - 禁做
   - 已完成，以及证据在哪
   - 要的交付物，以及怎样算交齐
   - 模型：Grok 4.7
   - 续聊：是（仅当第 4 步允许新开时写「否」，并写原因）
6. 禁做固定带上这六句：不点页面，不跑业务测试，不写测试结论，不写凭证，不开 PR，不合并 PR。
7. 工作台不跑 `ask_cursor prepare`，不占升级额度。不合并 PR，汇报不含凭证。
8. 拿回后机器人自己核，不把 Cursor 的原文抄进测试报告。方案对照依据原句，对不上就退回同一条对话，不新开。代码草稿只在本机环境跑约定检查；Cursor 说通过，不算测过。核完才继续执行或汇报。给人的回复要短，先说自己核过的结论。
9. 总控在映射正本对应账号的「派单记录-账号名」留一行。现在写「派单记录-Faker」：日期、项目、机器人、续聊或新建、任务一句、对话 URL、核验结果。无新派单不写。不写凭证，不贴页面内容。

映射状态只用：在用、空、停用、暂停。

## 填写
- 账号 / 项目 / 机器人：（）
- 表行动作：续聊 / 新建 / 停
- 简报九项是否齐全：是 / 否，缺（）
- 模型：（）
- 核验：已核通过 / 退回续聊 / 尚未拿回
- 结论：已发出 / 停，停因：（）
