本文件对照现网「工作台填空」改文字。不用仓库旧正文覆盖现网技能 id。文件里没有现网技能 id 链接时，不补写 id。

花名册该项目状态是暂停（含 nova，以及已停的 M3，含支付）时，本技能结束：不建工作台、不续聊、不写映射表、不叫醒。技能存在不等于暂停项目开工。日报、走查、周报不建工作台。壳号不建。GO 尚无 Project，不预建，不新建 GO Project。

## 停手
1. 简报缺下面任一项：停，不发。问句固定为：「简报缺（字段名），请补这一项。」依据没有时，依据栏写「无依据，停」，这份简报不发。盯守方、长任务（是或否）也算必填。新建或改未放行用例正文时，撰写人没写明也停。
2. 本次要改共享框架并且要开 PR：本技能停笔，改走「Cursor专家升级」和 `ask_cursor`，同一问题只保留一个案例、一个 Agent、一个 PR。工作台里只留案例链接，不在工作台开 PR。
3. 不是下面「可以新开」的三种情况：必须续聊，不新开窗口。
4. 准备写成「没有入口」或「没有协调器」之前：按 `grokbot/BACKUP.md`「恢复与同步检查清单」核`工作台-<当前账号>`。需要对照时再看来源账号的页、最新完整备份和较新的增量或 skill-sync 包。方向不写死。当前账号页是空的、仓库旧快照、停用标签、当前账号 Projects 列表没有记录，都不能单独当成缺失。旧机器人停用不等于对话失效。无权限或找不到不是可以重建。能复用就复用并补登；窗口在、映射缺，就补映射。确实未建、且现有规则要求有工作台，才按规则建角色主对话或需求子对话并读回。本技能不新建 Project 协调器。JoinProject 和新建 Project 仍要用户当轮允许。暂停项目只核离线映射，不唤醒、不派工、不测试。

## 谁来做
本机器人写简报并贴进自己的工作台。总控先查表、告诉续哪一条、写映射表，不代写项目简报。思考、方案、改代码草稿交给 Cursor；点页面、跑脚本、取证、写测试结论仍由机器人自己做。有主管的项目，派活由主管分配，总控只转达。

## 步骤
1. 先打开 Google Drive 表「QA机器人Cursor工作台」（只按表名查找，技能和仓库不写表链接、对话 id）。查本项目、本机器人那一行。归属 Project 与 `grokbot/skills/project-bot-collab/CURSOR-WORKBENCH.md`「归属 Project」一致：T8T 业务常驻挂 T8T；总控和通用问题挂「通用」，工作台映射与协作约定也放这里；独立项目「工作台映射与约定」停用，不再使用，本技能不归档它；测试专用 Project 保留，不并进通用。
2. 已有对话且状态是「在用」：必须续聊，把简报贴进该对话，并请总控把「上次续聊日期」改成当天。
3. 没有行，或对话列为空：先看花名册该不该有常驻工作台。在用号且应建常驻的，按花名册预建到对应 Project，不改成等第一笔活才建。GO 尚无 Project，不预建，不新建 GO Project。需求分析不预建，有独立需求再开一条，不并进常驻行。日报、走查、周报、壳号、暂停号：不建，本步结束。要建时：默认模型 Grok 4.7，上下文 256K，力度 High，打开 Fast。建在仓库 `qa-agent-team` 下，不要无仓库。建完由总控写入：对话地址、对话 id、模型、状态「在用」、开设日期、归属 Project。职责上下文用 `grokbot/templates/cursor-workbench-brief.md`，写入该 Project 下的常驻工作台。
4. 只有这三种情况可以新开，且须总控先把旧地址写入「上一条 URL」、旧状态改成「停用」，再把新地址写入原行。不删旧行：
   - 对话打不开、已过期或无法继续发送；
   - 上下文已经串项目，或同一问连续两次答非所问；
   - 新启用一个非暂停号，花名册要求它有常驻工作台，而该行还没有对话。按花名册预建到对应 Project。日报、走查、周报、壳号、暂停号不建。需求分析不在此列。
   换一天、换一条用例、想要空白窗口，都续聊。跨项目框架问题进常驻 Plan，不进任何一个项目工作台。
5. 简报必须写满原来这八项，再加盯守方、长任务（是或否）。缺一项不发：
   - 项目
   - 任务（一句）
   - 依据（知识点编号或文档位置；没有写「无依据，停」）
   - 禁做
   - 已完成，以及证据在哪
   - 要的交付物，以及怎样算交齐
   - 模型：Grok 4.7
   - 续聊：是（仅当第 4 步允许新开时写「否」，并写原因）
   - 盯守方
   - 长任务：是或否
   新建或改未放行用例正文时，简报还要写明撰写人。机器人写就写该机器人名，Cursor 工作台写就写「Cursor」。与执行人分开。不要只为补这个字段去改已放行正文。已有用例不批量回填，除非用户再说。
6. 禁做固定带上这六句：不点页面，不跑业务测试，不写测试结论，不写凭证，不开 PR，不合并 PR。
7. 工作台不跑 `ask_cursor prepare`，不占升级额度。不合并 PR，汇报不含凭证。
8. 拿回后机器人自己核，不把 Cursor 的原文抄进测试报告。方案对照依据原句，对不上就退回同一条对话，不新开。代码草稿只在本机环境跑约定检查；Cursor 说通过，不算测过。核完才继续执行或汇报。给人的回复要短，先说自己核过的结论。回归须当轮现取证，不得用旧截图或旧数据当结论。
9. 总控在同一张表的「派单记录」页留一行：日期、项目、机器人、续聊或新建、任务一句、核验结果。无新派单不写。不写凭证，不贴页面内容。

映射表状态只用：在用、空、停用、暂停。

### 长任务

按 CURSOR-WORKBENCH「长任务沟通与盯检」执行。派单时只做这四步：

1. 先查这单有没有负责人、有没有在用对话、有没有别的号已接。有则只续原盯守方，不另发，不另开。
2. 简报加两格：盯守方；长任务是或否。不拆活时，盯守方写本对话。要拆或要汇合时，盯守方写本项目协调器，并且这份简报不贴进子线程，不贴进第二条对话。
3. 发出之后不追问进度。只把三种回音当数：交齐、阻塞、范围要改。见到已记录、待命、不必告诉用户：不回复。
4. 总控只把用户能用的那一次结论转出去，附执行方聊天入口。同一事实不说第二次。

## 用例复核

机器人把一批用例设计好并写入用例库后，由本项目测试执行发复核简报。任务写复核。走该项目测试执行号的常驻对话，不发到写这批用例的需求分析对话，不新开「用例评审」用途行。同一项目、同一需求标识的复核续同一条常驻。该号还没有常驻、且这是第一笔思考活时，才按本技能建常驻行。八项简报仍要齐，另加盯守方、长任务。要的交付物是建议放行、退回改、待核实（缺依据），以及逐条或按编号的理由。禁做仍带本技能那六句。细则与 `grokbot/skills/case-review/SKILL.md` 同一句，这里不另定口径。
